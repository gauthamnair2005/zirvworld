What is MOSIX?

MOSIX (Modern OSIX) is an open operating system standard that modernises the traditional POSIX/FHS model for contemporary hardware and software needs. Like POSIX, MOSIX defines:

  • A filesystem hierarchy with simplified, descriptive paths
  • A device namespace replacing /dev, /sys, /proc, and /run
  • A syscall ABI for x86-64 (with provision for other architectures)
  • A security model (MAEM for in-memory encryption)
  • Design conventions for userspace interfaces

MOSIX is not tied to any specific kernel. Zirvium is the reference implementation — a from-scratch x86-64 kernel that fully implements the specification — but anyone can build a MOSIX-compliant kernel, libc, shell, or distribution. MOSIX is not related to the historical MOSIX distributed OS from the 1990s.

The MOSIX standard addresses four key areas:

  • Unified device namespace — Replace /dev, /sys, /proc, and /run with a single /zirv hierarchy
  • Simplified filesystem hierarchy — Reduce the FHS to essential directories only
  • Modern syscall ABI — Drop obsolete syscalls, add modern equivalents
  • Memory encryption — Enforce encryption of sensitive in-memory data

Filesystem Hierarchy

MOSIX replaces the traditional FHS (Filesystem Hierarchy Standard) with a simplified layout:

PathMOSIXReplaces (POSIX)Purpose
/Root/Root directory
/binSystem binaries/bin, /sbin, /usr/bin, /usr/sbinAll executables in one place
/libLibraries/lib, /usr/libShared and static libraries
/userUser home area/home, /rootHome directories for all users
/bootBoot/bootBootloader and kernel images
/configConfiguration/etcSystem-wide configuration files
/zirvDevice namespace/dev, /sys, /proc, /runAll device, system, and runtime data
/mountsMount points/mnt, /mediaFilesystem mount points
/tmpTemporary files/tmpWorld-writable temporary storage

Design rationale

  • /bin merges all executable directories. No distinction between "user" and "system" binaries
  • /user replaces both /home and /root with a single hierarchy
  • /config uses a descriptive name rather than the cryptic /etc
  • /zirv unifies four separate hierarchies into one, simplifying device discovery

System Call ABI

MOSIX defines an x86-64 syscall ABI based on the Linux convention but with MOSIX-specific extensions. Any kernel implementing this ABI can run MOSIX userspace programs compiled against zirvlibc (or any other MOSIX-compliant libc).

RAX = syscall number
RDI = arg1  RSI = arg2  RDX = arg3
R10 = arg4  R8  = arg5  R9  = arg6
Return: RAX = result (positive/zero) or negative errno on error
Instruction: SYSCALL (enters ring 0), SYSRETQ (returns to ring 3)

Error convention

Negative errno: -ENOMEM = -12, -EBADF = -9, -EINVAL = -22, -EPIPE = -32.

MAEM Security Standard

MAEM (Memory-Attested Encryption of Surfaces) is a MOSIX security specification for encrypting sensitive in-memory data. The reference implementation targets display framebuffers.

Requirements

  1. Encryption at rest: All surface buffers encrypted in memory at all times
  2. Per-surface keys: Each surface must have a unique encryption key
  3. Hardware entropy: Key derivation must use RNG (RDRAND or equivalent)
  4. Cryptographic wipe: On deallocation, buffers are cryptographically destroyed
  5. Key separation: One surface's key must not compromise others

Cryptographic primitives

EncryptionChaCha20 (20 rounds, 32-byte key, 12-byte nonce, 32-bit counter)
Key derivationHKDF (SHA-256 based)
HashSHA-256 (FIPS 180-4, 64-round compression)
EntropyRDRAND (primary) with software fallback

Design Principles

  1. Minimality: Define only what is needed. No obsolete interfaces
  2. Security by default: Encrypt sensitive data in memory
  3. Flat hierarchy: No deep nesting. /zirv replaces /dev + /sys + /proc + /run
  4. Self-describing devices: Everything in /zirv has a type, bus, and index
  5. Freestanding-first: The userspace ABI does not depend on any libc
  6. Open standard: Anyone can implement MOSIX. Zirvium is the reference
