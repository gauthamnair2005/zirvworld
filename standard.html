What is MOSIX?

MOSIX (Modern OSIX) is an operating system standard that modernises the traditional POSIX/FHS model for contemporary hardware and software needs. It was designed alongside the Zirvium kernel to provide a clean, minimal, and secure foundation for operating system development. MOSIX is not related to the historical MOSIX distributed OS from the 1990s.

The MOSIX standard addresses four key areas of modernisation:

  • Unified device namespace — Replace /dev, /sys, /proc, and /run with a single /zirv hierarchy
  • Simplified filesystem hierarchy — Reduce the FHS to essential directories only
  • Modern syscall ABI — Drop obsolete syscalls, add modern equivalents
  • Memory encryption — Enforce encryption of sensitive in-memory data (display surfaces, key material)

Filesystem Hierarchy

MOSIX replaces the traditional FHS (Filesystem Hierarchy Standard) with a simplified layout:

PathMOSIXReplaces (POSIX)Purpose
/Root/Root directory
/binSystem binaries/bin, /sbin, /usr/bin, /usr/sbinAll executables in one place
/libLibraries/lib, /usr/libShared and static libraries
/userUser home area/home, /rootHome directories for all users
/bootBoot/bootBootloader and kernel images
/configConfiguration/etcSystem-wide configuration files
/zirvDevice namespace/dev, /sys, /proc, /runAll device, system, and runtime data
/mountsMount points/mnt, /mediaFilesystem mount points
/tmpTemporary files/tmpWorld-writable temporary storage

Design rationale

  • /bin merges all executable directories. No distinction between "user" and "system" binaries — all are equally important
  • /user replaces both /home and /root. A single hierarchy for all users including root
  • /config uses a descriptive name rather than the cryptic /etc
  • /zirv unifies four separate hierarchies into one, simplifying device discovery and reducing mount overhead

The /zirv Device Namespace

The /zirv directory is the single entry point for all device, system, and runtime information. It replaces /dev, /sys, /proc, and /run from traditional Unix systems.

Device naming convention

/zirv/<bus>/<type><index>

Where <bus> is the hardware bus (sata, pata, nvme, usb, net, input, display, tty, audio), <type> is a media/function type descriptor, and <index> is a zero-based instance counter. Examples: /zirv/sata/disk0, /zirv/net/wlan0, /zirv/display/gpu0, /zirv/tty/virtual0.

System Call ABI

MOSIX defines an x86-64 syscall ABI based on the Linux convention but with custom extensions. Syscall numbers 0-99 follow the Linux x86-64 assignments where applicable; numbers 96-101 and 110-120 are MOSIX-specific.

Calling convention

RAX = syscall number
RDI = arg1  RSI = arg2  RDX = arg3
R10 = arg4  R8  = arg5  R9  = arg6
Return: RAX = result (positive or zero) or negative errno on error
Instruction: SYSCALL (enters ring 0), SYSRETQ (returns to ring 3)

Error convention

Negative errno values in RAX on failure: -ENOMEM = -12, -EBADF = -9, -EINVAL = -22, -EPIPE = -32. The libc wrappers return -1 and set internal state.

MAEM Security Standard

MAEM (Memory-Attested Encryption of Surfaces) is a MOSIX security specification for encrypting sensitive in-memory data. The initial implementation targets display framebuffers, but the architecture is general.

Requirements

  1. Encryption at rest: All surface buffers must be stored encrypted in memory at all times
  2. Per-surface keys: Each surface must have a unique encryption key
  3. Hardware entropy: Key derivation must use hardware random number generation when available
  4. Cryptographic wipe: On deallocation, the buffer must be overwritten with encrypted garbage before pages are freed
  5. Key separation: Access to one surface must not compromise other surfaces

Cryptographic primitives

EncryptionChaCha20 (20 rounds, 32-byte key, 12-byte nonce, 32-bit counter)
Key derivationHKDF (extract: SHA-256 with salt, expand: iterative SHA-256 with counter)
HashSHA-256 (FIPS 180-4, 64-round compression)
EntropyRDRAND (primary) with xorshift64+RDTSC fallback

Design Principles

  1. Minimality: Define only what is needed. No obsolete interfaces (STREAMS, SysV IPC, etc.)
  2. Security by default: Encrypt sensitive data in memory, don't trust physical memory access
  3. Flat hierarchy: No deep nesting. /zirv replaces /dev + /sys + /proc + /run with one flat namespace
  4. Self-describing devices: Everything in /zirv has a type, bus, and index. No guesswork about hardware
  5. Freestanding-first: The userspace ABI does not depend on a libc. C library is a convenience, not a requirement
  6. English-like interfaces: Where possible, userspace tools accept natural language input
