1. Overview

Zirvium is an x86-64 operating system that implements the MOSIX (Modern OSIX) standard. It boots on bare metal hardware and in emulators like QEMU.

The user-facing system consists of three layers:

  • Kernel (zirvium) — Handles hardware, memory, processes, and drivers
  • Init (zirvinit) — PID 1, displays boot banner and launches the shell
  • Shell (zirvshell) — The command-line interface with English-like syntax

2. Building the OS

System requirements

  • A Linux or BSD system with build tools (for building)
  • x86-64-elf cross-compiler (or system gcc)
  • NASM >= 2.14
  • GNU Make
  • grub-mkrescue + xorriso (to create bootable ISO)
  • mtools (to create bootable ISO)

Step-by-step build

# 1. Install dependencies (Ubuntu/Debian)
sudo apt install build-essential nasm grub-pc-bin grub-common \
                 xorriso mtools qemu-system-x86

# 2. Clone the repository
git clone https://github.com/gauthamnair2005/zirvium.git
cd zirvium

# 3. Fetch submodules (zirvinit, zirvshell, zirvutils)
git submodule update --init

# 4. Build the kernel ELF
make

# 5. Build a bootable ISO image
make iso

# 6. (Optional) Build individual components
make -C zirvinit       # just the init binary
make -C zirvshell      # just the shell binary
make -C zirvlibc       # just the C library

Build outputs

build/zirvium.elfKernel ELF binary (Multiboot2-compatible)
build/zirvium.isoBootable CD-ROM image (GRUB2)
zirvinit/zirvinit.elfInit binary
zirvshell/zirvshell.elfShell binary
zirvlibc/libzirvlibc.aC library archive

3. Running in QEMU

Quick start

make run

This single command builds the ISO and launches QEMU with the following configuration:

  • Serial console redirected to your terminal
  • 512 MiB RAM
  • Standard VGA display in an SDL window
  • IDE disk (blank 10 MiB image)
  • VirtIO block device
  • Three NICs: Intel e1000, VirtIO net, and Realtek RTL8139
  • Boot from CD-ROM (-boot d)

Manual QEMU invocation

qemu-system-x86_64 \
    -cdrom build/zirvium.iso \
    -serial stdio \
    -m 256M \
    -vga std \
    -display sdl

4. Boot Process

When Zirvium boots, the following happens in sequence:

  1. GRUB2 loads the kernel from ISO and transfers control
  2. Boot stub (assembly) sets up long mode page tables, loads GDT, and enters 64-bit mode
  3. kernel_main initialises subsystems in order:
    1. Serial port (COM1)
    2. CPU: GDT, IDT, PIC interrupts
    3. Memory: physical and virtual memory managers
    4. Console: VGA text mode
    5. Filesystem: MOSIX VFS tree
    6. Process table
    7. System calls (SYSCALL MSRs)
    8. PCI bus enumeration
    9. Device drivers (dynamic probing)
    10. PS/2 keyboard
  4. PID 1 (zirvinit) is created, loaded from the embedded ELF, and started in user mode
  5. zirvinit prints its banner and executes /bin/shell (zirvshell)
  6. zirvshell displays its banner and presents the prompt

6. MOSIX Filesystem

The MOSIX standard replaces the traditional FHS (Filesystem Hierarchy Standard) with a simplified, modern layout:

/Root directory
/binSystem binaries (init, shell, utilities)
/libSystem libraries
/userUser home area
/bootBoot configuration
/configSystem configuration
/zirvDevice namespace (replaces /dev, /sys, /run)
/mountsMount points
/tmpTemporary files

The current VFS implementation is in-memory only (no persistent storage driver yet). Directory entries exist as defined above; file operations for device nodes are handled by their respective drivers.

7. The /zirv Device Namespace

The /zirv directory unifies device management under a single hierarchy, replacing the traditional /dev, /sys, and /run split:

/zirv/sata/SATA (AHCI) storage devices
/zirv/pata/PATA (IDE) storage devices
/zirv/nvme/NVMe SSD devices
/zirv/usb/USB mass storage devices
/zirv/net/Network interfaces
/zirv/input/Input devices (keyboard, touchpad)
/zirv/display/Display/graphics devices
/zirv/tty/Terminal/console devices
/zirv/audio/Audio devices

Console device

The primary console device is at /zirv/tty/virtual0:

  • Read: Accepts input from both PS/2 keyboard and serial port
  • Write: Outputs simultaneously to VGA text mode, pixel framebuffer, and serial port
  • Colour support: ANSI escape sequences render with VGA attributes and framebuffer pixel colours

8. Building zirvlibc

The C library can be built standalone:

cd zirvlibc
make          # produces libzirvlibc.a
make test     # runs unit tests

The test suite verifies:

  • String operations: memcpy, memmove, memset, strcpy, strcmp, strstr, etc.
  • Character classification: isspace, isdigit, isalpha, toupper, etc.
  • printf formatting: %s, %d, %u, %x, %p, %c, %% with snprintf truncation

9. Frequently Asked Questions

What is MOSIX?

MOSIX (Modern OSIX) is a rethinking of the POSIX standard designed for modern hardware. It replaces legacy paths (/dev, /sys, /proc) with a unified /zirv namespace, simplifies the FHS hierarchy, and drops obsolete interfaces.

Is Zirvium compatible with Linux binaries?

No. Zirvium implements its own MOSIX syscall ABI (x86-64). While the syscall numbers happen to overlap with Linux in some cases, the semantics, behaviour, and available calls are entirely MOSIX-specific. Programs must be compiled specifically for Zirvium using the provided toolchain and zirvlibc.

What hardware does Zirvium support?

Currently: x86-64 CPUs with long mode, PCI bus, SATA (ATA PIO), NVMe, USB storage (stub), PS/2 keyboard, Synaptics touchpad, serial UART (16550), VGA text mode, pixel framebuffer, Bochs VGA, VMware SVGA, Intel i915 graphics, HDA audio, Intel e1000 NIC, VirtIO net/block, Realtek RTL8139 NIC, Realtek RTL8723DE WiFi, Realtek Bluetooth, and TPM 2.0.

Can I boot Zirvium on real hardware?

Yes. Write build/zirvium.iso to a USB/CD and boot via UEFI/BIOS with GRUB2. However, real hardware support is experimental and hardware-specific drivers (AHCI, XHCI, etc.) may need additional work.

Why is malloc not implemented?

malloc in zirvlibc is a stub returning NULL because the OS does not yet have a fully-featured heap for userspace. The brk and mmap syscalls are implemented and can be used directly. A proper malloc implementation is planned.

How do I exit the shell?

Type exit. This will cause the shell to return, and since there is no scheduler to start another process, the system will effectively stop.

10. Troubleshooting

"Failed to load zirvinit.elf"

The ELF binary may be corrupted or missing. Rebuild with make -C zirvinit clean && make -C zirvinit then rebuild the kernel with make.

QEMU shows a black screen

Ensure you're using -serial stdio to see the serial output. The VGA display may not render if the framebuffer mode fails. Try -vga std.

"mformat not found" when running make iso

Install mtools: sudo apt install mtools (Debian/Ubuntu) or sudo pacman -S mtools (Arch).

"grub-mkrescue: not found"

Install GRUB utilities: sudo apt install grub-pc-bin grub-common xorriso.

Cross-compiler not found

The build system falls back to the system gcc, which may produce incompatible code. Install or build an x86_64-elf-gcc cross-compiler (see the developer docs for instructions).

No response to keyboard input in QEMU

Make sure the QEMU window has focus. The PS/2 keyboard driver requires the emulated PS/2 controller which is enabled by default in QEMU.

The shell command "cat" says "not yet implemented"

The cat command is a stub awaiting the VFS read implementation for regular files. Device node reads (e.g., /zirv/tty/virtual0) work through the console device.
