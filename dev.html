1. Toolchain Setup

Zirvium requires a cross-compiler targeting x86_64-elf. The build system will fall back to the system gcc if the cross-compiler is not installed, but this is not recommended for production builds.

Building a cross-compiler (recommended)

export PREFIX=/usr/local/cross
export TARGET=x86_64-elf
export PATH="$PREFIX/bin:$PATH"

# Binutils
wget https://ftp.gnu.org/gnu/binutils/binutils-2.42.tar.xz
tar xf binutils-2.42.tar.xz
mkdir build-binutils && cd build-binutils
../binutils-2.42/configure --target=$TARGET --prefix=$PREFIX --disable-nls
make -j$(nproc)
make install

# GCC
wget https://ftp.gnu.org/gnu/gcc/gcc-13.2.0/gcc-13.2.0.tar.xz
tar xf gcc-13.2.0.tar.xz
mkdir build-gcc && cd build-gcc
../gcc-13.2.0/configure --target=$TARGET --prefix=$PREFIX \
  --disable-nls --enable-languages=c --without-headers
make -j$(nproc) all-gcc
make install-gcc

Other requirements

  • NASM >= 2.14
  • GNU Make
  • grub-mkrescue + xorriso (for ISO images)
  • mtools (for ISO images)
  • QEMU (for testing)

2. Building the Kernel

Basic build

git clone https://github.com/gauthamnair2005/zirvium.git
cd zirvium
git submodule update --init
make

This produces build/zirvium.elf, a static ELF64 binary linked at 0xFFFFFFFF80000000 with the boot stub at 1 MiB.

Build targets

makeBuild kernel ELF only
make isoBuild a GRUB2 bootable ISO image
make runBuild ISO and run in QEMU
make debugBuild ISO and launch QEMU with GDB stub on port 1234
make binStrip the ELF to a flat binary
make cleanRemove all build artefacts

Makefile variables

CCC compiler (default: x86_64-elf-gcc, fallback: gcc)
LDLinker (default: x86_64-elf-ld)
ASAssembler (default: nasm)

The kernel is compiled with -mcmodel=kernel -mno-red-zone -ffreestanding. The KERNEL preprocessor define is set, which controls conditional compilation in shared headers (e.g., stdio.c excludes write-based output when built for kernel space).

4. Boot Process

Stage 1: GRUB2 (Multiboot2)

The kernel ELF contains a Multiboot2 header. GRUB2 loads the kernel at physical address 0x100000 (1 MiB) and jumps to the entry point in boot.asm with EAX = 0x36D76289 (Multiboot2 magic) and EBX pointing to the Multiboot2 info structure.

Stage 2: boot.asm (32-bit to 64-bit)

  1. Disables interrupts (CLI)
  2. Sets up a minimal boot stack
  3. Checks CPUID availability and long mode support
  4. Builds 4-level page tables with 2 MiB huge pages:
    • Identity map: 0x00000000 - 0x100000000 (4 GiB)
    • Higher-half map: 0xFFFFFFFF80000000 (kernel)
  5. Loads a 64-bit GDT with kernel code/data segments
  6. Performs a far jump into long mode
  7. Sets up segment registers and calls kernel_main

Stage 3: kernel_main

The init sequence in kernel/main.c proceeds as follows:

1. serial_init(SERIAL_COM1)         -- Early serial output
2. gdt_init()                       -- GDT with user segments
3. idt_init()                       -- IDT with 256 ISR entries
4. irq_init()                       -- PIC remap (IRQ 0-15 -> INT 32-47)
5. Parse Multiboot2 memory map
6. pmm_init()                       -- Physical memory bitmap
7. vmm_init()                       -- 4-level paging, PHYS_MAP_BASE
8. vga_init()                       -- VGA text mode buffer
9. console_init()                   -- Console subsystem
10. vfs_init()                      -- MOSIX directory tree
11. proc_init()                     -- Process table
12. embedded_init()                 -- Embedded binary table
13. syscall_init()                  -- SYSCALL MSRs
14. pci_init()                      -- PCI bus enumeration
15. driver_register() / probe      -- Dynamic drivers
16. i8042_init() / keyboard_init() -- PS/2 keyboard
17. proc_create(0)                  -- Create PID 1
18. elf_load_process(PID 1, init)  -- Load zirvinit.elf
19. proc_enter_usermode(PID 1)     -- Jump to ring 3

5. Physical Memory Manager

File: kernel/mm/pmm.c, kernel/mm/pmm.h

The PMM uses a bitmap allocator with one bit per 4 KiB page frame. Bit = 1 means the frame is in use; bit = 0 means it is free. The bitmap is statically allocated in BSS and supports up to 1 TiB of physical memory (268 million frames, 32 MiB bitmap).

Key data structures

static uint64_t bitmap[BITMAP_WORDS];   // BITMAP_WORDS = MAX_PMM_PAGES / 64
static size_t total_pages;               // total discovered RAM pages
static size_t free_pages;                // currently free pages
static size_t search_start;              // next allocation hint

Initialisation

pmm_init takes the Multiboot2 memory map tag address, entry size, and total size. It marks all bits as used (bitmap[i] = ~0ULL), then iterates the memory map entries: for each MB2_MMAP_AVAILABLE entry it clears the corresponding bits in the bitmap and increments the free page count.

API reference

pmm_alloc_page()Allocate a single 4 KiB frame. Returns physical address or 0 on OOM.
pmm_free_page(phys)Free a single frame by physical address.
pmm_alloc_pages(count)Allocate a contiguous run of frames. Returns first physical address.
pmm_free_pages(phys, count)Free a contiguous run of frames.
pmm_total_pages()Return total number of RAM frames.
pmm_free_page_count()Return number of free frames.

Allocation algorithm

Single page allocation scans from search_start to total_pages, then wraps around from 1 to search_start. This provides basic locality. Multi-page allocation scans for a contiguous run of free bits.

6. Virtual Memory Manager

File: kernel/mm/vmm.c, kernel/mm/vmm.h

The VMM manages x86-64 4-level paging: PML4 → PDP → PD → PT. Each table has 512 entries covering 9 bits of the virtual address. Page size is 4 KiB (with 2 MiB huge page support).

Virtual memory layout

0x0000000000000000 - 0x00007FFFFFFFFFFF   User space (per-process)
0xFFFF800000000000 - 0xFFFFFFFF7FFFFFFF   PHYS_MAP_BASE (direct physical map)
0xFFFFFFFF80000000 - 0xFFFFFFFFFFFFFFFF   Kernel image (KERNEL_VIRT_BASE)

Key constants

KERNEL_VIRT_BASE0xFFFFFFFF80000000
KERNEL_PHYS_BASE0x200000 (2 MiB)
PHYS_MAP_BASE0xFFFF800000000000

Page table entry flags

PTE_PRESENTPage is in memory
PTE_WRITABLEWritable
PTE_USERAccessible from ring 3
PTE_HUGE2 MiB page (at PD level)
PTE_GLOBALNot flushed on CR3 switch
PTE_NO_EXECExecute disabled (NX bit)

API reference

vmm_init()Set up kernel address space with identity map, PHYS_MAP, kernel image
vmm_map_page(as, virt, phys, flags)Map a single 4 KiB page
vmm_unmap_page(as, virt)Unmap a single page
vmm_virt_to_phys(as, virt)Translate virtual to physical address
vmm_create_address_space()Create a new PML4 with kernel upper-half cloned
vmm_destroy_address_space(as)Free all user pages and tables
vmm_switch_address_space(as)Load CR3 to activate address space
vmm_clear_user_space(as)Free all user-space pages (for process exit)

PHYS_TO_VIRT macro

The PHYS_TO_VIRT(p) macro converts a physical address to a directly-mapped virtual address: (void *)((uintptr_t)(p) + PHYS_MAP_BASE). This is the primary way kernel code accesses arbitrary physical memory.

7. Kernel Heap

File: kernel/mm/heap.c

A bump allocator over a 4 MiB static arena. Each allocation has a header with a magic marker for integrity checking:

#define HEAP_SIZE        (4 * 1024 * 1024)
#define HEAP_MAGIC_ALLOC  0xA110CA7E
#define HEAP_MAGIC_FREE   0xFEEDF00D

typedef struct {
    uint32_t magic;          // HEAP_MAGIC_ALLOC when in use
    size_t   size;           // aligned payload size
} heap_hdr_t;

Known limitation: kfree marks the header with HEAP_MAGIC_FREE but does not coalesce adjacent free blocks or return pages to the PMM. Freed memory is not reused. This is acceptable for early-stage kernel drivers but will be replaced with a slab/page allocator in a future phase.

kmalloc(size, flags)Allocate from the bump arena (16-byte aligned)
kzalloc(size, flags)Allocate zeroed memory
kcalloc(n, size, flags)Allocate zeroed array
kfree(ptr)Mark as freed (no reuse, no coalescing)
krealloc(ptr, new_size, flags)Allocate new block, copy, free old

8. Process Management

Files: kernel/proc/process.c, kernel/proc/process.h

Process descriptor

typedef struct process {
    uint32_t         pid;
    proc_state_t     state;       // UNUSED, RUNNING, BLOCKED, ZOMBIE
    address_space_t *as;          // per-process page tables
    uint64_t         user_rip;    // entry point or saved RIP
    uint64_t         user_rsp;    // saved user stack pointer
    uint64_t         kstack_top;  // TSS kernel stack (for IRQ from ring 3)
    uint64_t         brk;         // program break (heap end)
    uint64_t         mmap_cursor; // mmap allocation cursor
    open_file_t     *fds[64];     // file descriptor table
    int              exit_code;
    struct process  *parent, *child, *next_sibling;
    char             cwd[256];
    struct process  *next;        // global process list
} process_t;

User virtual memory layout

PROC_USTACK_TOP    0x0000700000000000   User stack (grows down, 64 KiB)
PROC_HEAP_START    0x0000100000000000   Initial brk
PROC_MMAP_START    0x0000200000000000   First mmap VA

API reference

proc_init()Initialise process list
proc_create(entry_virt)Create a new process with fresh address space and stack
proc_enter_usermode(proc)Switch to process stack, load CR3, IRETQ to ring 3
proc_current()Return the currently running process
proc_exit(proc, code)Mark process as zombie with exit code
proc_alloc_fd(proc, file)Allocate a file descriptor
proc_get_fd(proc, fd)Get open file by descriptor
proc_close_fd(proc, fd)Close a file descriptor
proc_link_child(parent, child)Link child into parent's process tree

User mode entry

proc_enter_usermode performs the following critical sequence:

  1. Sets TSS.RSP0 to the process's kernel stack (so interrupts from ring 3 use the right stack)
  2. Saves user RIP/RSP into local variables (survives stack switch)
  3. Switches to the per-process kernel stack (the boot stack will be lost after CR3 switch because it's only identity-mapped)
  4. Switches address space (loads CR3)
  5. Pushes SS, RSP, RFLAGS, CS, RIP as an IRET frame
  6. Executes IRETQ to jump to ring 3

Calling convention

RAX = syscall number
RDI = arg1  RSI = arg2  RDX = arg3
R10 = arg4  R8  = arg5  R9  = arg6
Return: RAX = result or negative errno

Entry handler (syscall_entry.asm)

  1. Swap to per-CPU kernel stack (load from syscall_kernel_stack_top)
  2. Push callee-saved registers (RBX, RBP, R12-R15)
  3. Swap R10 (arg4) into RCX for the C ABI
  4. Call syscall_dispatch(num, a1, a2, a3, a4, a5, a6)
  5. On return, restore registers and SYSRETQ

Syscall dispatch rules

  • read/write: Looks up the file descriptor, dispatches to VFS read/write or pipe read/write based on type
  • open: Looks up the path in VFS, allocates an open file descriptor
  • mmap: Supports anonymous mappings only (PROT_READ|WRITE, MAP_PRIVATE|ANONYMOUS)
  • brk: Grows or shrinks the program break, mapping/unmapping pages as needed
  • execve: Finds the binary via embedded_find, loads it into the current process, replaces address space (old pages are freed)
  • exit: Calls proc_exit, then halts
  • uptime: Returns seconds since boot from time_uptime_seconds()
  • getdatetime/setdatetime: Read/write the CMOS RTC via the time subsystem
  • gettz/settz: Query/set the system timezone offset in minutes
  • reboot: Writes ACPI reset register (0xCF9: 0x0E then 0x06), falls back to keyboard controller (0x64: 0xFE)
  • shutdown: Writes QEMU exit port (0x604: 0x2000) and Bochs exit port (0xB004: 0x2000)
  • getdents: Read directory entries from a VFS directory node

Error convention

All syscalls return a negative errno value in RAX on failure (e.g. -ENOMEM = -12, -EBADF = -9, -EINVAL = -22). The libc wrappers negate the value for errno-style reporting.

11. Inter-Process Communication

File: kernel/ipc/pipe.c, kernel/ipc/pipe.h

Ring-buffer pipes with a 4 KiB circular buffer.

Data structure

typedef struct pipe {
    uint8_t  buf[4096];       // ring buffer
    uint32_t read_pos;        // consumer index
    uint32_t write_pos;       // producer index
    uint32_t count;           // bytes in buffer
    bool     read_closed;
    bool     write_closed;
} pipe_t;

EOF semantics: pipe_read returns 0 (EOF) when write_closed is true AND the buffer is empty. If data is still buffered, it returns remaining bytes first.

API

pipe_create()Allocate and initialise a pipe
pipe_read(pipe, buf, count)Read from pipe (spin-waits for data)
pipe_write(pipe, buf, count)Write to pipe
pipe_destroy(pipe)Free pipe buffer

12. Interrupt Handling

File: kernel/irq/irq.c

  • 8259A PIC remapped: IRQ 0-15 → IDT vectors 32-47
  • request_irq(irq, handler, flags): Register a handler for an IRQ
  • irq_dispatch(int_no): Called from the common ISR stub, routes to registered handlers
  • irq_eoi(int_no): Send End-of-Interrupt to PIC
  • Supports shared IRQs and edge triggering

The common ISR dispatch (isr_dispatch in main.c) checks: if int_no < 32, it's a CPU exception (panic). Otherwise it calls irq_dispatch.

13. Driver Framework

Device Registry

File: drivers/zirv/device.c

Each hardware device gets an entry in the /zirv namespace. The registry assigns a unique device path based on bus type and instance counter:

zirv_register_device(bus, media, ops, priv) → creates /zirv/<bus>/<media><n>

The driver vtable (zirv_device_ops_t) supports:

  • init — Initialise device
  • read_sectors / write_sectors — Block I/O
  • ioctl — Device control
  • shutdown — Power down

Dynamic Driver Probing

File: drivers/zirv/driver.c

Drivers are registered via driver_register() with a vendor/device ID table. During driver_probe_all(), each PCI device is matched against the driver table and the first matching driver's init() is called.

Registered drivers in main.c:

  • Bochs VGA
  • VMware SVGA
  • TPM 2.0
  • Intel e1000
  • VirtIO net / block
  • Realtek RTL8139

Linux Driver Compatibility Layer

File: drivers/compat/linux_compat.h (610 lines)

This layer ports existing Linux drivers to MOSIX/Zirvium with a comprehensive API bridge. It provides:

  • Type mappings: u8/u16/u32/u64, __le16/32/64, phys_addr_t, dma_addr_t
  • Bit operations: set_bit, clear_bit, test_bit, BIT(), GENMASK()
  • Memory/MMIO: readb/w/l/q, writeb/w/l/q, ioremap, iounmap, memcpy_from/toio, memset_io
  • Barriers: mb(), rmb(), wmb(), READ_ONCE/WRITE_ONCE
  • Synchronisation: spinlock_t, mutex_t, atomic_t, atomic64_t, completion, wait_queue_head_t
  • Memory management: kzalloc, kfree, kmalloc, kcalloc, krealloc, devm_* stubs
  • Linked lists: list_head, list_add/del/for_each, hlist
  • PCI helpers: pci_read/write_config_*, pci_resource_start/len, pci_enable_device
  • DMA API: dma_alloc_coherent, dma_free_coherent, dma_map_single
  • IRQ/timers: request_irq/free_irq, timer_list, del_timer, jiffies
  • Logging: pr_debug/info/warn/err, dev_dbg/info/warn/err
  • Utility: min/max/clamp, ERR_PTR/PTR_ERR/IS_ERR, container_of, kref

An NVIDIA GPU stub (drivers/zirv/nvidia.c) demonstrates the bridge by probing via pci_compat and conditionally initialising the device. This dramatically reduces the fear of driver availability — if hardware has a Linux driver, it can be adapted for Zirvium.

14. ELF Binary Loader

File: kernel/loader/elf.c

Loads static ELF64 binaries into a process address space.

Load process

  1. Read ELF header: validate magic (\x7fELF), class (64-bit), encoding (little-endian), version
  2. Iterate program headers (e_phoff, e_phnum)
  3. For each PT_LOAD segment:
    • Align virtual address to page boundary
    • Allocate physical pages for each page in the segment
    • Map pages into process address space at the ELF-specified VA
    • Copy segment data from ELF file
    • Zero-fill p_memsz - p_filesz bytes (BSS)
  4. Set proc->user_rip = ehdr->e_entry

Embedded binaries

File: kernel/loader/embedded.c, kernel/loader/init_bin.asm

Multiple userspace ELF binaries are embedded into the kernel via NASM incbin. The embedded_init function records their addresses and sizes; embedded_find(path) returns the binary data by path.

15. Console Subsystem

Syscall wrappers (src/syscall.c)

Each wrapper uses inline assembly to invoke the syscall instruction:

long _syscall3(long n, long a1, long a2, long a3) {
    long ret;
    __asm__ volatile("syscall"
        : "=a"(ret)
        : "a"(n), "D"(a1), "S"(a2), "d"(a3)
        : "rcx", "r11", "memory");
    return ret;
}

Arguments are passed in RDI, RSI, RDX, R10, R8, R9 per the x86-64 SYSCALL ABI. The rcx and r11 clobbers are required because SYSCALL saves RIP into RCX and RFLAGS into R11.

printf implementation

vsnprintf is a self-contained formatter in src/stdio.c. It supports %s, %d, %u, %x, %p, %c, %% with a sink-based output model. When built for userspace (#ifndef KERNEL), it wraps the formatter with printf/vprintf that call the write syscall.

Building

make          # produces libzirvlibc.a
make test     # builds and runs unit tests

Unit tests in test_libc.c verify string operations (memcpy, strcmp, strstr, memmove), character classification, and printf formatting.

17. zirvinit

Directory: zirvinit/

The init system is a minimal static ELF binary (zirvinit.elf, ~28 lines C + 20 lines assembly). Its complete source:

int main(void) {
    printf("\n  Z I R V I N I T\n");
    printf("  ---------------\n");
    printf("  MOSIX Compliant PID 1\n\n");
    printf("[ INIT ] Starting MOSIX lifecycle...\n");
    printf("[ INIT ] Verifying /zirv namespace...\n");
    printf("[ INIT ] Launching ZirvShell...\n");
    execve("/bin/shell", argv, envp);
    printf("[ INIT ] execve failed!\n");
    for (;;) ;
}

crt0.asm

The entry point calls main, and if it ever returns, falls back to SYS_EXIT:

_start:
    call main
    mov rax, 60    ; SYS_EXIT
    xor rdi, rdi
    syscall
.halt: hlt; jmp .halt

Build

make -C zirvinit

19. Porting Guide

Porting the kernel to a new architecture

  1. Create arch/<arch>/ with:
    • Boot code (stub entry point)
    • Context switch code
    • Interrupt dispatch
    • MMU/page table management
    • Timer/clock source
  2. Implement arch/<arch>/cpu.h (port I/O, barriers, special registers)
  3. Implement arch/<arch>/gdt.h (or equivalent privilege-level mechanism)
  4. Implement arch/<arch>/idt.h (or equivalent interrupt vector table)
  5. Add the new arch to the Makefile's source lists
  6. Update the linker script for the target's memory layout

Writing a new driver

  1. Implement the driver init/read/write/ioctl functions
  2. Create a zirv_driver_t struct with vendor/device IDs
  3. Register via driver_register(&my_driver) in kernel/main.c
  4. The PCI subsystem will call my_driver.init(pci_device) during probe if vendor/device match
  5. In init(), call zirv_register_device(bus, media, ops, priv) to create the /zirv entry

Adding a syscall

  1. Add a new SYS_* constant in kernel/syscall/syscall.h
  2. Add the same constant in libs/zirvlibc/include/zirv/syscall.h
  3. Implement the handler function in kernel/syscall/syscall.c
  4. Add the dispatch case to syscall_dispatch
  5. Add a wrapper in libs/zirvlibc/src/unistd.c
  6. Add the prototype in libs/zirvlibc/include/unistd.h

21. Writing MOSIX Userspace Programs

This section is a complete guide to creating your own programs that run on Zirvium. MOSIX userspace programs are static ELF64 binaries that use the MOSIX x86-64 syscall ABI and link against zirvlibc.

21.1 Program Lifecycle

  1. The kernel ELF loader maps your binary into a process address space
  2. The kernel sets up a stack and jumps to _start (the ELF entry point)
  3. Your crt0.asm calls main()
  4. Your program runs, makes syscalls via zirvlibc wrappers
  5. Your program calls exit() or _exit(), which invokes SYS_EXIT
  6. The kernel reclaims all memory and marks the process as a zombie

21.2 Required Files

Every MOSIX userspace program needs three files:

1. crt0.asm — C runtime entry point

; crt0.asm — MOSIX userspace entry point
; Assembles with: nasm -f elf64 crt0.asm -o crt0.o
[bits 64]
section .text
global _start
extern main

_start:
    ; The kernel passes:
    ;   RDI = argc
    ;   RSI = argv (pointer to array on stack, if any)
    ; For now we call main with no arguments.
    xor rbp, rbp        ; mark stack frame boundary
    mov rdi, 0          ; argc = 0
    mov rsi, 0          ; argv = NULL
    call main

    ; If main returns, exit with its return value
    mov rdi, rax        ; status = main return value
    mov rax, 60         ; SYS_EXIT
    syscall

.halt:
    hlt
    jmp .halt

2. main.c — Your program

#include <stdio.h>      // printf, puts, putchar
#include <string.h>     // strlen, strcmp, memset, memcpy
#include <unistd.h>     // read, write, open, close, getpid, brk, execve
#include <stdlib.h>     // exit, atoi

int main(void)
{
    printf("Hello from MOSIX!\n");
    printf("My PID is %d\n", getpid());
    return 0;
}

3. Makefile — Build system

# Makefile — MOSIX userspace program
CC      := x86_64-elf-gcc
LD      := x86_64-elf-ld
AS      := nasm

# Path to zirvlibc (adjust to your setup)
LIBC_DIR := ../zirvlibc

CFLAGS := \
    -std=c11 \
    -ffreestanding \
    -fno-stack-protector \
    -fno-pic \
    -mno-red-zone \
    -mno-mmx -mno-sse -mno-sse2 \
    -Wall -Wextra -O2 \
    -I$(LIBC_DIR)/include

LDFLAGS := \
    -nostdlib \
    -static \
    -no-pie \
    -z max-page-size=0x1000

# zirvlibc source files to compile and link
LIBC_SRCS := \
    $(LIBC_DIR)/src/string.c \
    $(LIBC_DIR)/src/ctype.c \
    $(LIBC_DIR)/src/stdio.c \
    $(LIBC_DIR)/src/unistd.c \
    $(LIBC_DIR)/src/syscall.c \
    $(LIBC_DIR)/src/stdlib.c

LIBC_BUILD := build/libc
LIBC_OBJS := $(patsubst $(LIBC_DIR)/src/%.c,$(LIBC_BUILD)/%.o,$(LIBC_SRCS))

SRCS := main.c crt0.asm
OBJS := main.o crt0.o

TARGET := myprogram.elf

.PHONY: all clean

all: $(TARGET)

$(TARGET): $(OBJS) $(LIBC_OBJS)
	$(LD) $(LDFLAGS) -o $@ $^

%.o: %.c
	$(CC) $(CFLAGS) -c -o $@ $<

%.o: %.asm
	$(AS) -f elf64 -o $@ $<

$(LIBC_BUILD)/%.o: $(LIBC_DIR)/src/%.c
	@mkdir -p $(@D)
	$(CC) $(CFLAGS) -c -o $@ $<

clean:
	rm -f $(TARGET) $(OBJS)
	rm -rf $(LIBC_BUILD)

21.3 Compiler and Linker Flags Explained

-ffreestandingNo standard library startup; the compiler does not assume a hosted environment
-fno-stack-protectorNo canary code (there is no thread-local storage for the canary)
-fno-picPosition-dependent code (no GOT/PLT needed)
-mno-red-zoneNo 128-byte red zone below RSP (important because kernel/IRQ stacks may clobber it)
-mno-mmx -mno-sse -mno-sse2No SIMD instructions (the kernel does not save/restore FPU state on context switch)
-nostdlibDo not link against the host's standard library
-staticProduce a fully static binary (no dynamic linking support)
-no-pieNo position-independent executable (the loader expects fixed load addresses)
-z max-page-size=0x1000Use 4 KiB page alignment for segments

21.7 Step-by-Step: Using mmap for Memory

#include <stdio.h>
#include <unistd.h>
#include <string.h>

int main(void)
{
    // Allocate 64 KiB of anonymous memory
    long addr = mmap(NULL, 65536,
                     PROT_READ | PROT_WRITE,
                     MAP_PRIVATE | MAP_ANONYMOUS,
                     0, 0);
    if (addr == (long)MAP_FAILED) {
        printf("mmap failed!\n");
        return 1;
    }

    printf("Allocated 64 KiB at 0x%x\n", (unsigned int)addr);

    // Use the memory
    char *buf = (char *)addr;
    memcpy(buf, "MOSIX mmap works!", 18);
    printf("%s\n", buf);

    // Free it
    munmap((void *)addr, 65536);
    printf("Memory freed.\n");

    return 0;
}

21.9 Using the Program Break (brk/sbrk)

#include <stdio.h>
#include <unistd.h>
#include <string.h>

int main(void)
{
    // Query current break
    void *cur = sbrk(0);
    printf("Current program break: 0x%x\n", (unsigned int)(unsigned long)cur);

    // Allocate 4096 bytes by moving the break forward
    void *new_break = sbrk(4096);
    printf("Old break: 0x%x\n", (unsigned int)(unsigned long)new_break);

    // Use the memory
    char *data = (char *)new_break;
    memcpy(data, "Heap data!", 11);
    printf("%s\n", data);

    // Check new break
    void *after = sbrk(0);
    printf("New program break: 0x%x\n", (unsigned int)(unsigned long)after);

    return 0;
}

21.10 Using Pipes for IPC

#include <stdio.h>
#include <unistd.h>
#include <string.h>

int main(void)
{
    int fds[2];

    // SYS_PIPE is syscall 22; the C library wrapper is pipe().
    // For now, use the raw syscall since the pipe wrapper
    // may not be exposed in unistd.h.
    long result;
    __asm__ volatile("syscall"
        : "=a"(result)
        : "a"(22), "D"(fds)
        : "rcx", "r11", "memory");

    if (result < 0) {
        printf("pipe() failed\n");
        return 1;
    }

    printf("Pipe created: read_fd=%d write_fd=%d\n", fds[0], fds[1]);

    // Write to the write end
    char *msg = "Hello through pipe!";
    write(fds[1], msg, strlen(msg));

    // Read from the read end
    char buf[64];
    int n = read(fds[0], buf, sizeof(buf) - 1);
    buf[n] = '\0';
    printf("Read from pipe: %s\n", buf);

    // Close both ends
    close(fds[0]);
    close(fds[1]);

    return 0;
}

21.11 Embedding Your Program into the Kernel

To make your program available at boot time (accessible via execve("/bin/myprogram", ...)), you embed it into the kernel binary. This is how zirvinit and zirvshell are included.

Step 1: Add an incbin section

Edit kernel/loader/init_bin.asm:

section .rodata

global zirvinit_bin_start, zirvinit_bin_end
zirvinit_bin_start: incbin "zirvinit/zirvinit.elf"
zirvinit_bin_end:

global zirvshell_bin_start, zirvshell_bin_end
zirvshell_bin_start: incbin "zirvshell/zirvshell.elf"
zirvshell_bin_end:

; Add your program here:
global myprogram_bin_start, myprogram_bin_end
myprogram_bin_start: incbin "myprogram/myprogram.elf"
myprogram_bin_end:

Step 2: Register the binary

Edit kernel/loader/embedded.c. Add the extern declarations and register in embedded_init():

extern char myprogram_bin_start[];
extern char myprogram_bin_end[];

// In embedded_init():
embedded_add("/bin/myprogram",
             (uintptr_t)myprogram_bin_start,
             (uintptr_t)myprogram_bin_end - (uintptr_t)myprogram_bin_start);

Step 3: Add your program to the Makefile

In the top-level Makefile, add your program's ELF as a dependency of init_bin.asm.o:

MYPROGRAM_ELF := myprogram/myprogram.elf

# Add to the dependency line:
$(BUILD_DIR)/kernel/loader/init_bin.asm.o: \
    kernel/loader/init_bin.asm \
    $(ZIRVINIT_ELF) $(ZIRVSHELL_ELF) $(ZIRVUTILS_ELFS) \
    $(MYPROGRAM_ELF)

# Add a build rule:
$(MYPROGRAM_ELF):
	$(MAKE) -C myprogram

Step 4: Rebuild

make clean && make iso

Your program is now embedded in the kernel and can be executed from ZirvShell with run /bin/myprogram or exec /bin/myprogram.

21.14 Known Limitations

  • malloc/free: These are stubs returning NULL. Use sbrk() or mmap() directly for dynamic memory.
  • No stdlib.h functions: Only exit, abort, atoi, and atol are implemented. No qsort, rand, etc.
  • No floating point: The kernel does not save/restore the FPU, MMX, or SSE state. Avoid float/double types.
  • No thread support: The kernel has no multi-threading (only processes).
  • No signals: Signal syscalls are not implemented.
  • No filesystem persistence: The VFS is in-memory only; file data is lost on reboot.
  • Single process at a time: While the kernel supports multiple processes, there is no scheduler yet — only PID 1 runs.
