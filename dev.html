1. Toolchain Setup

Zirvium requires a cross-compiler targeting x86_64-elf:

export PREFIX=/usr/local/cross
export TARGET=x86_64-elf
export PATH="$PREFIX/bin:$PATH"

# Binutils 2.42
wget https://ftp.gnu.org/gnu/binutils/binutils-2.42.tar.xz
tar xf binutils-2.42.tar.xz
mkdir build-binutils && cd build-binutils
../binutils-2.42/configure --target=$TARGET --prefix=$PREFIX --disable-nls
make -j$(nproc)
make install

# GCC 13.2.0
wget https://ftp.gnu.org/gnu/gcc/gcc-13.2.0/gcc-13.2.0.tar.xz
tar xf gcc-13.2.0.tar.xz
mkdir build-gcc && cd build-gcc
../gcc-13.2.0/configure --target=$TARGET --prefix=$PREFIX \
  --disable-nls --enable-languages=c --without-headers
make -j$(nproc) all-gcc
make install-gcc

Other requirements: NASM >= 2.14, GNU Make, grub-mkrescue + xorriso, mtools, QEMU.

2. Building the Kernel

git clone https://github.com/gauthamnair2005/zirvium.git
cd zirvium
git submodule update --init --recursive
make

Produces build/zirvium.elf, linked at 0xFFFFFFFF80000000 with boot stub at 1 MiB.

Build targets

Compiler flags: -std=c11 -ffreestanding -mcmodel=kernel -mno-red-zone -fno-pic -fno-stack-protector -mno-mmx -mno-sse -mno-sse2 -DKERNEL -O2

4. Boot Process

Stage 1: GRUB2 loads kernel at 0x100000, jumps to boot.asm with Multiboot2 magic.

Stage 2: arch/x64/boot.asm — disables interrupts, checks CPUID/long mode, builds 4-level page tables (identity map 0-4 GiB + higher-half at 0xFFFFFFFF80000000), loads 64-bit GDT, far-jumps into long mode, calls kernel_main.

Stage 3: kernel_main — 20-step init sequence (serial, GDT, IDT, PIC, memory, console, VFS, processes, syscalls, time, PCI, drivers, keyboard) then creates PID 1 and jumps to ring 3.

5. Physical Memory Manager

File: kernel/mm/pmm.c — Bitmap allocator, 1 bit per 4 KiB frame (supports 1 TiB max).

static uint64_t bitmap[BITMAP_WORDS];   // BITMAP_WORDS = MAX_PMM_PAGES / 64
static size_t total_pages, free_pages, search_start;

Initialisation: all bits set to 1 (used), then Multiboot2 memory map entries mark available regions as 0 (free). Page 0 is always reserved.

API: pmm_alloc_page, pmm_free_page, pmm_alloc_pages (contiguous), pmm_free_pages, pmm_total_pages, pmm_free_page_count.

Allocation uses sequential scan with wrap-around hint for locality.

6. Virtual Memory Manager

File: kernel/mm/vmm.c — x86-64 4-level paging (PML4 → PDP → PD → PT).

0x0000000000000000 - 0x00007FFFFFFFFFFF   User space
0xFFFF800000000000 - 0xFFFFFFFF7FFFFFFF   PHYS_MAP_BASE
0xFFFFFFFF80000000 - 0xFFFFFFFFFFFFFFFF   Kernel image

Page table entry flags

PTE_PRESENTPage is in memory
PTE_WRITABLEWritable
PTE_USERAccessible from ring 3
PTE_HUGE2 MiB page
PTE_GLOBALNot flushed on CR3 switch
PTE_NO_EXECExecute disabled (NX bit)

PHYS_TO_VIRT(p): (void *)((uintptr_t)(p) + PHYS_MAP_BASE) — primary method for kernel to access arbitrary physical memory.

7. Kernel Heap

File: kernel/mm/heap.c — Bump allocator over 4 MiB static arena. Headers have magic markers for integrity checking (HEAP_MAGIC_ALLOC = 0xA110CA7E, HEAP_MAGIC_FREE = 0xFEEDF00D).

Limitation: kfree marks free but does not coalesce or reuse. Will be replaced with a slab allocator.

API: kmalloc, kzalloc, kcalloc, kfree, krealloc.

8. Process Management

Files: kernel/proc/process.c, kernel/proc/process.h

typedef struct process {
    uint32_t         pid;
    proc_state_t     state;       // UNUSED, RUNNING, BLOCKED, ZOMBIE
    address_space_t *as;
    uint64_t         user_rip, user_rsp;
    uint64_t         kstack_top;  // TSS kernel stack (16 KiB)
    uint64_t         brk;         // program break
    uint64_t         mmap_cursor;
    open_file_t     *fds[64];
    int              exit_code;
    struct process  *parent, *child, *next_sibling;
    char             cwd[256];
    struct process  *next;
} process_t;

Memory layout

PROC_USTACK_TOP    0x0000700000000000   User stack (grows down, 64 KiB)
PROC_HEAP_START    0x0000100000000000   Initial brk
PROC_MMAP_START    0x0000200000000000   First mmap VA

No scheduler yet — single-process execution. PID 1 runs to completion. proc_enter_usermode switches to per-process kernel stack, loads CR3, builds IRETQ frame, executes IRETQ to ring 3.

Calling convention

RAX = syscall number
RDI = arg1  RSI = arg2  RDX = arg3
R10 = arg4  R8  = arg5  R9  = arg6
Return: RAX = result or negative errno

Dispatch rules

  • read/write: FD lookup → VFS or pipe dispatch based on type
  • mmap: Anonymous only (PROT_READ|WRITE, MAP_PRIVATE|ANONYMOUS)
  • brk: Grows/shrinks program break, maps/unmaps pages
  • execve: Finds binary via embedded_find, loads ELF, replaces address space
  • exit: Calls proc_exit, halts
  • uptime: TSC-based since boot
  • getdatetime/setdatetime: CMOS RTC via time subsystem
  • reboot: 0xCF9 = 0x0E then 0x06; KBC 0x64 = 0xFE
  • shutdown: 0x604 = 0x2000, 0xB004 = 0x2000

10. Time Subsystem

File: kernel/time/time.c

CMOS RTC

  • Reads from RTC registers (seconds, minutes, hours, day, month, year, century)
  • Auto-detects BCD vs binary and 12h vs 24h mode
  • Checks UIP (Update In Progress) bit for coherency
  • NMI mask bit preserved

TSC-based uptime

uint64_t time_uptime_seconds(void) {
    uint64_t now = rdtsc();
    uint64_t elapsed = now - g_boot_tsc;
    return elapsed / g_tsc_freq;
}

TSC frequency detected via CPUID leaf 0x15 (falls back to 2 GHz if unavailable). Boot TSC captured in time_init().

Timezone

Offset stored in minutes east of UTC. time_get() adds offset before returning. normalize_datetime() handles carry/borrow across all fields.

Default fallback: 2005-11-22 15:36:00 UTC

11. Virtual Filesystem

Files: fs/vfs.c, fs/mosix.h

In-memory directory tree using a 256 KiB static arena allocator. Standard MOSIX paths: /, /bin, /lib, /user, /boot, /config, /zirv (with per-bus subdirectories), /mounts, /tmp.

typedef struct vnode {
    char name[64];
    vnode_type_t type;       // DIRECTORY, DEVICE
    struct vnode *parent, *child, *next;
    vnode_ops_t *ops;
    void *private;
} vnode_t;

API: vfs_init, vfs_lookup, vfs_mount, vfs_register_device.

The console at /zirv/tty/virtual0 is the primary I/O endpoint: read polls PS/2 keyboard and serial; write outputs to serial + VGA + framebuffer.

12. Inter-Process Communication

File: kernel/ipc/pipe.c — Ring-buffer pipes with PIPE_BUF_SIZE (256 bytes). pipe_read returns 0 (EOF) when write end is closed and buffer empty. pipe_write returns -1 (EPIPE) when read end is closed.

13. Interrupt Handling

  • 8259A PIC remapped: IRQ 0-15 → IDT vectors 32-47
  • 256 ISR stubs in arch/x64/isr_stubs.asm
  • isr_dispatch: exceptions (int < 32) → panic; else → irq_dispatch
  • 4 slots per IRQ line for shared IRQs

14. Driver Framework

Device Registry

File: drivers/zirv/device.c — Assigns /zirv/<bus>/<type><n> paths. Driver vtable (zirv_device_ops_t): init, read_sectors, write_sectors, ioctl, shutdown.

Dynamic Driver Probing

Two-tier model:

  1. Native drivers: registered via driver_register(zirv_driver_t) with PCI vendor/device ID table. Match during driver_probe_all().
  2. Linux compat drivers: via pci_compat_register_driver(pci_driver_linux) for Linux-ported drivers.

Registered drivers: Bochs VGA, VMware SVGA, Intel i915, NVIDIA GPU (compat), TPM 2.0, Intel e1000, VirtIO net/block, Realtek RTL8139, Realtek RTL8723DE WiFi, Realtek Bluetooth.

Linux Compat Layer

File: drivers/compat/linux_compat.h (610 lines) — Comprehensive API bridge providing: type mappings, bit operations, MMIO accessors, memory barriers, spinlocks, mutexes, atomic ops, waitqueues, completions, timers, linked lists, PCI helpers, DMA API, logging, and utility macros.

15. ELF Binary Loader

File: kernel/loader/elf.c — Validates ELF64 header, iterates PT_LOAD, maps pages into process address space at ELF-specified VAs, zero-fills BSS. Sets proc->user_rip = ehdr->e_entry.

Embedded binaries (kernel/loader/embedded.c, init_bin.asm): 17 binaries via NASM incbin. embedded_find(path) returns binary data by path. The VMZIRV build mode (-DVMZIRV) produces a kernel with empty stub symbols (no embedded binaries).

16. Console Subsystem

File: kernel/console.c — Triple multiplexer: serial (COM1, 115200) + VGA text mode (80x25 at 0xB8000) + pixel framebuffer (glyph renderer). Colour-coded logging via klog(tag, component, format, ...).

17. zirvlibc Internals

Freestanding C library providing <string.h>, <ctype.h>, <stdio.h> (printf with %s%d%u%lu%llu%x%p%c%%, zero-padded width), <stdlib.h> (exit, atoi, atol; malloc is stub), <unistd.h> (read/write/open/close/execve/mmap/brk/sbrk/getpid/uptime/reboot/shutdown/gethostname/sethostname/getcwd/chdir/getdents), <datetime.h>, <dirent.h>, <zirv/syscall.h>.

Syscall wrappers use inline assembly (_syscall0 through _syscall6) with the x86-64 SYSCALL ABI. Build produces libzirvlibc.a.

18. zirvinit

Directory: zirvinit/ — 28 lines of C. PID 1 prints MOSIX banner and calls execve("/bin/shell", ...). Linked against zirvlibc, compiled with same freestanding flags as kernel.

19. zirvshell

Directory: zirvshell/ — 438-line REPL shell with English-like syntax. Features: CWD-aware prompt, line editor (backspace), double-quoted argument parsing, natural language commands (help me please, clear the screen).

All 19 shell commands implemented: help, echo/say, pwd/where, uname, whoami, clear, ls/list/show files, cat/display, run/exec, go to/cd, date, settime, timezone, uptime, reboot, shutdown/poweroff, suspend, exit.

20. Porting Guide

Porting to a new architecture

  1. Create arch/<arch>/ with boot code, context switch, interrupt dispatch, MMU management, timer
  2. Implement cpu.h (port I/O, barriers, special registers)
  3. Implement gdt.h (or equivalent privilege mechanism)
  4. Implement idt.h (or equivalent interrupt vector table)
  5. Update Makefile and linker script

Writing a new driver

  1. Implement init/read/write/ioctl functions
  2. Create zirv_driver_t with vendor/device IDs
  3. Register via driver_register(&my_driver) in kernel/main.c
  4. PCI subsystem calls my_driver.init(pci_device) on match
  5. Call zirv_register_device(bus, media, ops, priv) for /zirv entry

Adding a syscall

  1. Add SYS_* constant in kernel/syscall/syscall.h
  2. Add same constant in libs/zirvlibc/include/zirv/syscall.h
  3. Implement handler in kernel/syscall/syscall.c
  4. Add dispatch case to syscall_dispatch
  5. Add wrapper in libs/zirvlibc/src/unistd.c
  6. Add prototype in libs/zirvlibc/include/unistd.h

22. Writing MOSIX Userspace Programs

Userspace programs are static ELF64 binaries linked against zirvlibc. Each needs three files:

crt0.asm

[bits 64]
section .text
global _start
extern main
_start:
    xor rbp, rbp
    mov rdi, 0
    mov rsi, 0
    call main
    mov rdi, rax
    mov rax, 60
    syscall
.halt: hlt; jmp .halt

main.c

#include <stdio.h>
#include <unistd.h>

int main(void)
{
    printf("Hello from MOSIX! PID: %d\n", getpid());
    char cwd[256];
    if (getcwd(cwd, sizeof(cwd)) > 0)
        printf("CWD: %s\n", cwd);
    return 42;
}

Example: Using mmap

#include <stdio.h>
#include <unistd.h>
#include <string.h>

int main(void) {
    long addr = mmap(NULL, 65536,
        PROT_READ | PROT_WRITE,
        MAP_PRIVATE | MAP_ANONYMOUS, 0, 0);
    if (addr == (long)-1) {
        printf("mmap failed!\n");
        return 1;
    }
    char *buf = (char *)addr;
    memcpy(buf, "MOSIX mmap works!", 18);
    printf("%s\n", buf);
    munmap((void *)addr, 65536);
    return 0;
}

All flags explained: -ffreestanding (no libc startup), -fno-stack-protector (no TLS canary), -fno-pic (position-dependent), -mno-red-zone (no 128-byte below RSP), -mno-mmx -mno-sse -mno-sse2 (no SIMD), -nostdlib (no host libc), -static (fully static), -no-pie (fixed load address).

23. DisplayJet Driver API

Source: zirvdisplayjet

DisplayJet provides 11 custom syscalls (110–120) for a compositor-based display protocol. The driver drives Bochs VBE-compatible hardware at 1024x768x32bpp and encrypts all surfaces at rest using ChaCha20 with per-surface keys (MAEM).

Syscall interface

110dj_connect()Register as compositor (single-compositor model)
111dj_disconnect()Unregister, wipe all surfaces
112dj_create_surface(w, h, &id)Create MAEM-encrypted surface
113dj_destroy_surface(id)Crypto-wipe and free surface
114dj_present(id)Decrypt surface to scanout framebuffer
115dj_get_mode(&mode)Query display mode
116dj_surface_write(id, data, sz)Encrypt-and-store user data
117dj_surface_read(id, buf, sz)Decrypt surface to user buffer
118dj_list_surfaces(infos, &cnt)Enumerate active surfaces
119dj_request_access(id, &grant)Request access grant (stub)
120dj_grant_access(id, &grant)Derive ephemeral access key

MAEM encryption flow

Boot: RDRNAD (or xorshift64+RDTSC) → seed → HKDF("DisplayJet MAEM v1", seed) → g_master_key

Create surface: HKDF(g_master_key, surface_id) → per-surface key
                get_random_bytes() → 12-byte nonce

Write:   ChaCha20(key, nonce, counter, plaintext) → ciphertext stored in surface buffer
Present: ChaCha20(key, nonce, counter, ciphertext) → decrypted to scanout FB
Destroy: ChaCha20(0xFF..FF key, 0xFF..FF nonce, 0, buffer) → crypto wipe
         secure_zero(key, nonce)
         pmm_free_pages()

Key sizes: 32-byte keys, 12-byte nonces, 64-byte ChaCha20 blocks. Max 32 surfaces. Only format: RGBX8888 (32 bpp).

See the full DisplayJet documentation for complete details.

24. ZirvUI Compositor

Source: zirvui

ZirvUI is a user-space graphical compositor that connects to DisplayJet and renders a full desktop. It is compiled as a freestanding ELF binary (zirvui.elf) linked against zirvlibc and the DisplayJet userspace API.

Compositor flow

  1. dj_connect() — register as compositor
  2. dj_get_mode() — query display resolution
  3. dj_create_surface(fb_w, fb_h, &surf_id) — allocate encrypted surface
  4. Render desktop into local 3 MB framebuffer (1024x768x4):
    • Procedural background gradient
    • 28-pixel top panel with dark navy background
    • System tray icons: WiFi, Bluetooth, speaker, battery, user, power
    • Live uptime clock (MM:SS) using 5x7 bitmap font
    • Hamburger menu + "ZirvUI" branding
  5. dj_surface_write() — encrypt and upload full frame
  6. dj_present() — decrypt to scanout every ~1 second

5x7 bitmap font

96 glyphs (ASCII 32-126), 5 columns x 7 rows per glyph, packed as 5 bytes per glyph (one byte per column, bits 0-6 are rows). Spacing: 6 px per character (5 + 1 gap).

Key files

src/main.cCompositor main loop, rendering, DisplayJet protocol
src/crt0.asmEntry point, calls main, then SYS_EXIT
MakefileFreestanding x86_64-elf build

See the full ZirvUI documentation for complete details.
