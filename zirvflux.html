ZirvFlux — MOSIX Display Framework Library

ZirvFlux is the reference MOSIX display framework library. It provides a compositor-facing API for display enumeration, buffer management, and presentation — analogous to Mesa for Linux. Compositors like ZirvUI link against libzirvflux.a instead of calling the kernel display driver directly.

API

The library exposes the following operations through a simple C API defined in <zirvflux.h>:

zf_connect()Open the display device and register as compositor
zf_disconnect()Unregister compositor, release all buffers
zf_get_info()Query display dimensions and connector name
zf_create_buffer()Allocate a GPU surface (up to 32)
zf_destroy_buffer()Release a GPU surface
zf_write_buffer()Write pixel data to a buffer
zf_present()Flip a buffer to the screen
zf_present_region()Present a sub-region of a buffer
zf_list_buffers()Enumerate all allocated buffers

Implementation

The library communicates with the kernel display driver (DisplayJet) via custom MOSIX syscalls (110–120). Each buffer is encrypted at rest in kernel memory using ChaCha20 with a per-surface key derived via HKDF-SHA256.

Buffer size is 3 MB (ZF_BUFFER_SIZE_3MB), matching the 1024×768×32bpp framebuffer mode. The library handles the DisplayJet surface protocol, allowing compositors to work with a clean, Mesa-like API.

Build

make

Produces libzirvflux.a. Requires a freestanding C compiler (x86_64-elf-gcc or gcc).

Usage

#include <zirvflux.h>

zf_connect();
zf_display_info_t info;
zf_get_info(&info);
// info.width, info.height, info.connector

uint32_t buf_id;
zf_create_buffer(info.width, info.height, &buf_id);
// render pixels into a local framebuffer
zf_write_buffer(buf_id, pixel_data, size);
zf_present(buf_id);

Dependencies

  • zirvdisplayjet — Kernel display driver (syscalls 110–120)
  • zirvlibc — C library for syscall wrappers
