zirvium

C11 / ASM — GPLv3

The core x86-64 kernel. Zirvium implements 4-level paging, a bitmap-based physical memory manager (1 TiB max), a higher-half virtual memory manager, ELF64 binary loading, a MOSIX-compliant virtual filesystem, full PCI bus enumeration, and a dynamic driver framework. It boots via GRUB2 (Multiboot2) or Limine and produces a bootable ISO with make iso.

Syscalls (24 total): read, write, open, close, mmap, munmap, brk, pipe, getpid, execve, exit, wait4, uptime, getdents, getcwd, chdir, gethostname, sethostname, getdatetime, setdatetime, gettz, settz, reboot, shutdown. Numbers follow the Linux x86-64 ABI with MOSIX-specific extensions (13, 89-90, 96-101).

Key subsystems:

  • Memory: Bitmap PMM, 4-level VMM, bump-allocator kernel heap
  • Processes: Single-process execution (no scheduler yet), 64-entry FD table, per-process kernel stacks
  • IPC: Ring-buffer pipes with 4 KiB circular buffer, EOF semantics
  • Time: CMOS RTC driver, TSC-based uptime, timezone offset support
  • Console: Triple multiplexer (serial + VGA text + pixel framebuffer) with ANSI colour support
  • ELF loader: Static ELF64, PT_LOAD segment mapping, embedded binary table
  • Linux compat: 610-line linux_compat.h providing spinlocks, MMIO, DMA, PCI helpers for porting Linux drivers

zirvlibc

C11 — libzirvlibc.a

A minimal freestanding C library for MOSIX userspace programs. Provides the standard C functions needed by all Zirvium binaries, with inline syscall wrappers for the x86-64 SYSCALL ABI.

Implemented headers

string.hmemcpy, memmove, memset, memcmp, strlen, strnlen, strcpy, strncpy, strcmp, strncmp, strchr, strrchr, strstr
ctype.hisspace, isdigit, isalpha, isalnum, toupper, tolower
stdio.hvsnprintf, snprintf, vprintf, printf, puts, putchar — supports %s %d %u %lu %llu %x %p %c %% with zero-padded width
stdlib.hexit, abort, atoi, atol — malloc/free/calloc/realloc are stubs returning NULL
unistd.hread, write, open, close, _exit, getpid, brk, sbrk, execve, getcwd, chdir, mmap, munmap, uptime, reboot, shutdown, gethostname, sethostname
datetime.hgetdatetime, setdatetime, gettz, settz with struct datetime
dirent.hstruct dirent (ino + name[256]), getdents
zirv/syscall.hSyscall number definitions (SYS_READ=0 through SYS_SHUTDOWN=101), standard FD constants, error codes

Syscall wrappers

Inline assembly trampolines in src/syscall.c provide _syscall0 through _syscall6. Follows the x86-64 SYSCALL ABI: RAX = number, RDI = arg1, RSI = arg2, RDX = arg3, R10 = arg4, R8 = arg5, R9 = arg6.

Build produces libzirvlibc.a. Unit tests in tests/test_libc.c cover string, ctype, and stdio functions.

zirvinit

C11 / ASM — MOSIX init system (PID 1)

The first userspace process launched by the kernel. A minimal, standalone static ELF binary embedded as /bin/init. Its sole job is to print the MOSIX banner and launch ZirvShell via execve:

  Z I R V I N I T
  ---------------
  MOSIX Compliant PID 1

[ INIT ] Starting MOSIX lifecycle...
[ INIT ] Verifying /zirv namespace...
[ INIT ] Launching ZirvShell...

The entire init is 28 lines of C. It links against zirvlibc, uses crt0.asm for the entry point, and halts forever if execve fails.

make -C zirvinit produces zirvinit.elf.

zirvutils

C11 / ASM — 17 MOSIX embedded utilities

A suite of standard command-line utilities for the MOSIX environment. Each utility is compiled as a standalone static ELF64 binary, embedded into the kernel via init_bin.asm, and accessible from ZirvShell via run /bin/<name>.

zirvdisplayjet

C11 — MAEM-encrypted display driver (515 lines)

A display driver for the Zirvium kernel featuring MAEM (Memory-Attested Encryption of Surfaces). It drives Bochs VBE-compatible display hardware, exposing a userspace compositor API via 11 custom syscalls (110–120).

Key features:

  • Connect / disconnect compositor (single-compositor model)
  • Create and destroy GPU surfaces (up to 32, 1024x768x32bpp)
  • Surface read/write with ChaCha20 per-surface encryption
  • Per-surface keys derived via HKDF-SHA256 from a hardware-entropy master key
  • Cryptographic wipe on destroy (re-encrypt with all-0xFF key/nonce)
  • DMA fencing via access counters
  • Access grant mechanism with ephemeral key delegation
  • Entropy via RDRAND (with CPUID check) or xorshift64+RDTSC fallback

All framebuffer surfaces are encrypted at rest in kernel memory, ensuring that physical memory inspection cannot recover pixel data. Compiled as part of the Zirvium kernel build.

zirvui

C11 — MOSIX graphical desktop compositor

The ZirvUI desktop compositor / graphical shell for Zirvium. Connects to the DisplayJet driver to render a complete desktop environment with a modern panel, system status indicators, and a 5x7 bitmap font.

Features

  • Top panel with hamburger menu and "ZirvUI" branding
  • Status icons: WiFi, Bluetooth, speaker, battery, user, power button
  • Live uptime clock formatted as MM:SS
  • Background gradient with pixel-level compositing
  • 5x7 bitmap font (96 glyphs, ASCII 32-126) for all text elements
  • Fixed-point cos/sin lookup tables for circular icon rendering
  • Full-frame encrypted writes via DisplayJet surface protocol

Compiled as a freestanding ELF binary embedding zirvlibc and linking against the DisplayJet API. Produces zirvui.elf, embedded into the kernel at /bin/zirvui.
