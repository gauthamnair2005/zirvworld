Overview

ZirvUI is the graphical desktop compositor / graphical shell for the Zirvium operating system. It connects to the DisplayJet kernel driver via syscalls 110–125 and renders a complete multi-window desktop environment into a software framebuffer. It is a single-threaded user-space process compiled as a freestanding ELF binary (zirvui.elf) linked against zirvlibc and the ZirvFlux API.

Source: github.com/gauthamnair2005/zirvui

The display is 1920×1080 pixels. All rendering is procedural bitmap drawing directly into the software framebuffer — no GPU acceleration, no hardware overlays.

Screen Layers (back to front)

  1. Background: Procedural per-pixel vertical gradient. 6 wallpaper presets (Deep Blue, Twilight, Forest, Sunset, Ocean, Midnight) selectable from Settings → Display.
  2. Accent color: 8 accent color presets (Teal, Blue, Red, Green, Orange, Purple, Mint, Pink) applied to taskbar branding, clock text, settings headers, and demo app 3D canvas. Configurable from Settings → Display.
  3. Metro tile grid: 6×2 grid of coloured app tiles (120×120 px each, 16 px gap, 48 px margin). Clicking a tile launches the app with a smooth expand animation.
  4. Title bar: 36-pixel dark bar with back button and app name.
  5. Taskbar: 40-pixel bottom bar with "Zirvium" heading (accent-coloured), clock, exit and power buttons.
  6. Shutdown dialog: Modal confirmation overlay with animation

App Launch & Navigation

Opening an app

Click a tile on the start screen. A smooth ease-out animation plays: a coloured rect expands from the tile position to full screen, displaying the app icon and name. The animation speed is configurable in Settings → Display (Fast / Medium / Smooth).

After the animation, the app opens in full-screen mode. A 36-pixel title bar at the top shows the app name and a "< Back" button to return to the start screen (animated close).

App content

Each app draws its full UI into the client area below the title bar. Apps are single-process — they run as draw functions called from the compositor's main loop, not as separate processes.

Compositor Flow

  1. Connect: Call zf_connect() → DisplayJet syscall 110
  2. Query mode: Call zf_get_info(&info) → syscall 115 (get display resolution)
  3. Create buffer: Call zf_create_buffer(w, h, &buf) → syscall 112 (kernel allocates encrypted DMA buffer)
  4. Render: Software-render the full 1920×1080 frame into a local framebuffer:
    • Draw background gradient (6 wallpaper presets, selected via Settings)
    • Draw Metro tile start screen (9 app tiles in a 6×2 grid)
    • Draw taskbar with accent-coloured "Zirvium" heading, clock, exit/power buttons
    • If an app is active: draw title bar (with back button), then dispatch to app draw function
    • Draw animation overlay if an app is launching (smooth expand from tile)
    • Draw shutdown confirmation dialog if active
  5. Upload: Call zf_write_buffer(buf, compositor_fb, size) → syscall 116 (kernel encrypts with ChaCha20)
  6. Present: Call zf_present(buf) → syscall 114 (kernel decrypts to scanout framebuffer)
  7. Loop: 60 FPS paced via msleep(16). Dirty-tracked — only re-renders when something changes (mouse movement, keyboard input, clock tick, animation frame).

Drawing Primitives

All rendering uses a global draw offset (g_draw_off_x, g_draw_off_y) added to every fill_rect, draw_char, and draw_line call. The offset is set per-window before calling the app's draw function, so each app draws in its own coordinate system (0,0 = top-left of the client area).

Drawing Primitives (ZirvTK)

All pixel-level drawing operations now come from the ZirvTK GUI toolkit's raw-framebuffer module (rawfb.rs), exposed via C FFI as ztk_fb_* functions. The compositor calls ztk_fb_blend, ztk_fb_fill_rect, ztk_fb_hline, ztk_fb_draw_line, ztk_fb_draw_char_scaled, and ztk_draw_icon rather than using local C helpers. The 16 icon types (Terminal, Calculator, Files, Clock, Settings, Weather, Photos, Editor, Snake, Pong, Tetris, Music, Mail, Store, Maps, About) are rendered procedurally by ztk_draw_icon inside the toolkit. Anti-aliased character drawing remains local in the compositor for title-bar text and splash subtitle rendering.

The toolkit library libzirvtk.a is built via Cargo with --no-default-features (no std, no alloc) and linked into the compositor alongside libzirvflux.a. The compositor's Makefile compiles the Rust project, then the linker resolves all symbols, including freestanding stubs (bcmp, rust_eh_personality) in stubs.c that the precompiled Rust core library requires.

Font

8×13 pixel bitmap font (95 glyphs, ASCII 32–126) generated by tools/genfont.py and shared between the C compositor (font_8x13.h) and the ZirvTK Rust toolkit (font.rs). Anti-aliased rendering via alpha blending with 4-neighbour edge detection (edge pixels blend at alpha=180). Two font styles: Regular and Bold (computed at runtime by thickening strokes). Optional 2× scaling via ztk_fb_draw_char_scaled. All configurable from Settings → Display (Font Style, Font Size).

Icons

All app icons are rendered procedurally (coloured geometric shapes) by the toolkit's ztk_draw_icon. Each app tile on the start screen draws its icon centred in the tile at its app-specific colour.

Source Structure

zirvui/
  Makefile                Build system (freestanding ELF, builds libzirvtk.a)
  src/
    main.c                Compositor (~2120 lines)
    demoapp.c             Demo app (4 tabs: Shapes/3D/Widgets/Icons, ~405 lines)
    font_8x13.h           95×13 bitmap font data (C header, generated by genfont.py)
    crt0.asm              Entry point (_start → main → SYS_EXIT)
    stubs.c               Freestanding stubs for Rust core (bcmp, eh_personality)

The compositor integrates the ZirvTK Rust GUI toolkit via C FFI. The Makefile builds libzirvtk.a with cargo build --release --no-default-features and links it into the ELF. stubs.c provides symbols (bcmp, rust_eh_personality) that Rust's precompiled core library requires in a freestanding context. The toolkit supplies raw-framebuffer drawing primitives (ztk_fb_*), procedural icons (ztk_draw_icon), and the 8×13 bitmap font. The compositor retains around 2120 lines of C for start screen, app drawing, title bar, taskbar, boot splash, animations, and input handling. Font data is generated by a Python script (tools/genfont.py) shared with the toolkit.

Build

make    # Builds libzirvtk.a via Cargo, then links zirvui.elf

# C flags:
gcc -std=c11 -ffreestanding -fno-stack-protector -fno-pic
    -mno-red-zone -mno-mmx -mno-sse -mno-sse2 -O2
    -I../zirvtk/include

# Link:
ld -nostdlib -static -no-pie -z max-page-size=0x1000 \
    main.o crt0.o stubs.o libc/*.o libzirvtk.a libzirvflux.a

# Rust library (ZirvTK):
ZIRVFLUX_DIR=../zirvflux RUSTFLAGS="-C panic=abort" \
  cargo build --release --no-default-features --manifest-path ../zirvtk/Cargo.toml

Dependencies

  • zirvlibc (string, ctype, stdio, stdlib, unistd, syscall, datetime)
  • ZirvFlux (libzirvflux.a — display framework library)
  • ZirvTK (libzirvtk.a — Rust GUI toolkit with raw-framebuffer drawing primitives)

Animation System

App launch uses a smooth ease-out animation (smoothstep curve). The animation speed is configurable:

SettingFramesDuration (~60 FPS)
Fast5~83 ms
Medium (default)10~167 ms
Smooth20~333 ms

The animation runs as a smoothstep interpolation (t²·(3−2t)), expanding from the tile position to full screen. During the animation, mouse interaction and app drawing are suspended. The animation state advances one frame per iteration (~16 ms per frame at 60 FPS).
