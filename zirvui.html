Overview

ZirvUI is the graphical desktop compositor / graphical shell for the Zirvium operating system. It connects to the DisplayJet kernel driver via syscalls 110–125 and renders a complete multi-window desktop environment into a software framebuffer. It is a single-threaded user-space process compiled as a freestanding ELF binary (zirvui.elf) linked against zirvlibc and the ZirvFlux API.

Source: github.com/gauthamnair2005/zirvui

The display is 1920×1080 pixels. All rendering is procedural bitmap drawing directly into the software framebuffer — no GPU acceleration, no hardware overlays.

Screen Layers (back to front)

  1. Background: Procedural per-pixel gradient (deep purple to warm tones)
  2. Metro tile grid: 6×2 grid of coloured app tiles (140×140 px each, 16 px gap, 60 px margin). Clicking a tile launches the app with a flip+expand animation.
  3. Windows: Multiple floating windows with title bars, close buttons, drag-to-move, and snap-to-edges
  4. Chrome: "Zirvium" heading (top-left), exit and power buttons (top-right), date and clock (bottom-right). Chrome elements auto-hide when overlapped by a window title bar.
  5. Shutdown dialog: Modal confirmation overlay with animation

Window Management

Opening an app

Click a tile on the start screen. A two-phase animation plays:

  • Flip (8 frames, ~130 ms): The tile compresses vertically, simulating a card flip
  • Expand (16 frames, ~270 ms): A coloured rect eases out (2nd-order ease-out: t·(2−t)) from the tile position to full screen, displaying the app icon and name

After the animation, the window opens in full-screen mode (w = screen width, h = screen height).

Window chrome

  • Title bar: 28-pixel dark bar at the top of each window with the app name
  • Close button: Red square with an × at the top-right of the title bar (red hover highlight)
  • Drag: Click and hold the title bar to move the window freely. The window is constrained to the screen bounds.
  • Snap: Drag a window to the left or right screen edge (< 40 px threshold) → it snaps to half-screen width, full height. A coloured accent bar (3 px) appears on the snapped edge.
  • Bring to front: Clicking any window brings it to the front (Z-order is managed by reordering the array).

Chrome auto-hide

The "Zirvium" heading and the exit/power buttons in the top corners are only drawn when no window title bar overlaps them. A rect-overlap test runs for each chrome element against all active window title bars before drawing. The bottom-right date/clock are always visible (no title bar reaches that area).

Compositor Flow

  1. Connect: Call zf_connect() → DisplayJet syscall 110
  2. Query mode: Call zf_get_info(&info) → syscall 115 (get display resolution)
  3. Create buffer: Call zf_create_buffer(w, h, &buf) → syscall 112 (kernel allocates encrypted DMA buffer)
  4. Render: Software-render the full 1920×1080 frame into a local framebuffer:
    • Draw background gradient
    • Draw Metro tile start screen (12 app tiles in a scrollable 6×2 grid)
    • Draw all active windows (title bar, close button, snap indicator, client content)
    • Draw chrome overlay (heading, buttons, clock)
    • Draw animation overlay if an app is launching (flip + expand)
    • Draw shutdown confirmation dialog if active
  5. Upload: Call zf_write_buffer(buf, compositor_fb, size) → syscall 116 (kernel encrypts with ChaCha20)
  6. Present: Call zf_present(buf) → syscall 114 (kernel decrypts to scanout framebuffer)
  7. Loop: 60 FPS paced via msleep(16). Dirty-tracked — only re-renders when something changes (mouse movement, keyboard input, clock tick, animation frame).

Drawing Primitives

All rendering uses a global draw offset (g_draw_off_x, g_draw_off_y) added to every fill_rect, draw_char, and draw_line call. The offset is set per-window before calling the app's draw function, so each app draws in its own coordinate system (0,0 = top-left of the client area).

Font

8×13 pixel bitmap font (95 glyphs, ASCII 32–126) stored as a static array font_8x13[95][13] in main.c. Anti-aliased rendering via alpha blending with neighbouring-pixel tests. Optional 2× scaling in the Clock and Weather apps.

Icons

All app icons are rendered procedurally (coloured geometric shapes). Each app tile on the start screen draws its icon centred in the tile using the same draw_icon function with app-specific colours.

Build

make    # Produces zirvui.elf

# Flags:
gcc -std=c11 -ffreestanding -fno-stack-protector
    -fno-pic -mno-red-zone -mno-mmx -mno-sse -mno-sse2 -O2
ld -nostdlib -static -no-pie -z max-page-size=0x1000
as=nasm -f elf64

Dependencies

  • zirvlibc (string, ctype, stdio, stdlib, unistd, syscall, datetime)
  • ZirvFlux (libzirvflux.a — display framework library)

Animation System

App launch uses a two-phase animation based on the tile position:

PhaseFramesEffect
Flip8Tile height scales linearly from from_h to 0 (vertical squeeze)
Expand16Rect eases out from tile position/size to full screen using et = t·(2−t) with integer arithmetic (et_num / et_den)

During the animation, mouse interaction, window drawing, and chrome rendering are suspended. The animation state is checked in the main loop and advances one frame per iteration (~16 ms per frame).

  • True multi-process: Spawn apps as separate processes via SYS_SPAWN/SYS_FORK instead of calling draw functions in the compositor process
  • Window resize: Drag-to-resize from window edges and corners
  • Title bar minimize / maximise: Standard window control buttons
  • TrueType font rendering: Replace 8×13 bitmap font with scalable font support
  • Cursor rendering: Software-rendered mouse cursor with proper compositing
  • Hardware acceleration: Use GPU for composition
