Overview

DisplayJet is an in-kernel display driver for the Zirvium OS that provides a compositor-based display server protocol entirely in ring 0. It drives Bochs VBE-compatible display hardware (1024x768x32bpp) and implements the MAEM (Memory-Attested Encryption of Surfaces) security layer, encrypting every framebuffer surface at rest using ChaCha20 with per-surface keys derived via HKDF-SHA256.

The driver exposes 11 custom syscalls (110–120) for compositor management, surface creation/destruction, encrypted reads and writes, display mode querying, and access grants. A single compositor process connects at a time and manages up to 32 GPU surfaces.

Source: github.com/gauthamnair2005/zirvdisplayjet

Key concepts

  • Single compositor model: Only one process can connect as compositor at a time (enforced by g_dj.compositor_pid)
  • Surface pool: Up to 32 surfaces (DJ_MAX_SURFACES), each backed by physically-contiguous pages allocated from pmm_alloc_pages
  • Encrypted at rest: Every surface buffer is encrypted in kernel memory. Only decrypted transiently during read/present operations
  • Format: Only RGBX8888 (32 bits per pixel) is currently supported

MAEM Security Architecture

MAEM (Memory-Attested Encryption of Surfaces) ensures that display buffer data is never stored in plaintext, even in kernel memory. Physical memory inspection cannot recover pixel data.

┌─────────────────────────────────────────────────────────────────┐
│  Boot:                                                         │
│    RDRAND (or xorshift64+RDTSC) ──► 32-byte seed              │
│    HKDF("DisplayJet MAEM v1", seed) ──► g_master_key (32B)    │
│                                                                 │
│  Surface creation:                                              │
│    HKDF(g_master_key, surface_id, info=surface_id)             │
│      ──► per-surface s->key (32B)                              │
│    get_random_bytes() ──► s->nonce (12B)                       │
│    s->access_counter = 0                                       │
│    ChaCha20(s->key, s->nonce, counter=0, zeros) ──► buffer    │
│      (buffer encrypted immediately after allocation)           │
│                                                                 │
│  surface_write:                                                │
│    ChaCha20(s->key, s->nonce, counter=offset/64, plaintext)   │
│      ──► ciphertext stored in s->buffer                        │
│                                                                 │
│  surface_read / present:                                       │
│    ChaCha20(s->key, s->nonce, counter=offset/64, ciphertext)  │
│      ──► decrypted to caller's buffer / scanout               │
│                                                                 │
│  destroy / disconnect:                                         │
│    ChaCha20(all-0xFF key, all-0xFF nonce, 0, buffer)           │
│      ──► cryptographic wipe                                    │
│    secure_zero(s->key, s->nonce)                                │
│    pmm_free_pages()                                            │
│                                                                 │
│  grant_access:                                                 │
│    HKDF(s->key, g_master_key, info={counter, surface_id})     │
│      ──► ephemeral access grant key (32B)                      │
│    s->access_counter++                                         │
└─────────────────────────────────────────────────────────────────┘

Entropy sources

  • Primary: RDRAND instruction (CPUID leaf 1, ECX bit 30 checked before use)
  • Fallback: xorshift64 PRNG seeded with RDTSC (for QEMU without -cpu host)

Key sizes

Master key32 bytes (256-bit)
Per-surface key32 bytes (256-bit)
Nonce12 bytes (96-bit)
ChaCha20 block64 bytes
Access grant key32 bytes (256-bit)

Syscall API (110–120)

Note: the older DisplayJet documentation referenced syscalls up to 125, but the current implementation uses 110–120 (11 syscalls).

Userspace header: displayjet.h

#FunctionDescription
110dj_connect()Register calling process as compositor. Returns 0 on success. Only one compositor allowed.
111dj_disconnect()Unregister compositor. Crypto-wipes and frees all surfaces, resets surface ID counter.
112dj_create_surface(w, h, &id)Allocate DMA buffer, derive MAEM key, encrypt-empty. Returns surface ID via pointer.
113dj_destroy_surface(id)Crypto-wipe (all-0xFF re-encrypt) and pmm_free_pages the surface.
114dj_present(id)Decrypt surface buffer and copy to scanout framebuffer (4 KB chunks).
115dj_get_mode(&mode)Query display resolution, stride, BPP, connector name.

117dj_surface_read(id, buf, sz)Decrypt surface buffer to user buffer. Returns bytes read.
118dj_list_surfaces(infos, &cnt)Enumerate active surfaces (ID, width, height, stride, BPP).
119dj_request_access(id, &grant)Request access to a surface. Stub — always returns 0.

Hardware initialisation

  1. PCI scan for Bochs VBE: vendor 0x1234, device 0x1111 or 0x2111
  2. VBE I/O port programming: disable → set xres=1024, yres=768, bpp=32 → re-enable with LFB
  3. BAR0 mapping via pci_map_bar (uses PHYS_TO_VIRT)
  4. Version check: (ver & 0xB0C0) != 0xB0C0
  5. Register as DEV_CLASS_DISPLAY_GPU via zirv_register_device

Cryptographic Primitives

File: drivers/zirv/displayjet/crypto.c (231 lines) — All crypto is implemented from scratch in kernel space with no external library.

ChaCha20

IETF variant (RFC 8439-like): 20 rounds, 32-byte key, 12-byte nonce, 32-bit counter. State: "expand 32-byte k" constants, 8 key words, counter, 3 nonce words. Encryption: XOR keystream blocks with plaintext.

SHA-256

FIPS 180-4: standard 64-round compression with K constants. Streaming API: dj_sha256_init, dj_sha256_update (byte-by-byte), dj_sha256_final (padding + length encoding).

HKDF (simplified)

  • Extract: SHA256(salt_padded(64) || ikm) (non-standard, avoids HMAC)
  • Expand: Iterates SHA256(prk || info || counter) in 32-byte chunks

Secure zero

void dj_secure_zero(void *buf, size_t len) {
    volatile uint8_t *p = (volatile uint8_t *)buf;
    for (size_t i = 0; i < len; i++) p[i] = 0;
}

Uses volatile writes to prevent compiler optimisations from eliding the zeroing.

Access Grants (SUPS)

The access grant mechanism enables ephemeral key delegation between processes. When a compositor grants access to a surface, a derived key is created from the surface's key, the master key, and the current access counter. The grant key is time-limited (counter invalidates old grants) and surface-specific.

The comment in the source references SUPS (Secure User Prompt) — a future trusted-path UI for confirming access grants before they are issued.

Build & Integration

DisplayJet is compiled as part of the Zirvium kernel build. The Makefile is a placeholder that delegates to the kernel's top-level build:

make run    # DisplayJet is included automatically

The driver is integrated via:

  1. Source files placed in drivers/zirv/displayjet/
  2. Userspace header in include/displayjet.h
  3. Syscall dispatch cases added to kernel/syscall/syscall.c for numbers 110-120
  4. Initialisation called from kernel/main.c
