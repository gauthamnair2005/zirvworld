ZirvTK is the reference MOSIX GUI toolkit — a Rust library with C FFI containing the complete desktop compositor (ZirvTK Desktop) for MOSIX operating systems. It runs on top of the ZirvFlux display framework. The ZirvUI compositor is now a thin C stub that calls ztk_desktop_run() and blocks — all rendering, widgets, input handling, and the compositor loop live in ZirvTK.

Desktop Compositor

ZirvTK includes a full desktop compositor (Desktop) that renders a futuristic dark/neon/glass UI with:

  • Real-time clock — RTC-driven time display with anti-aliased scaled digits and formatted date (YYYY-MM-DD)
  • Taskbar — desktop panel with launcher dot button and system time
  • App Launcher — grid-based app menu with SVG vector path icons, animated hover pulse (sinusoidal glow), and app color assignments
  • Glass panels — semi-transparent UI panels with border stroke effects
  • Particle system — ambient floating particles with per-particle color cycling and velocity physics
  • Hardware cursor — DisplayJet hardware cursor only, no software cursor overhead
  • Tear-free rendering — VBE page flipping via DisplayJet Y_OFFSET flip for zero-tearing display updates

Canvas Rendering

  • Scanline-rounded rects — fill_round_rect and stroke_round_rect use scanline span fills (O(h) per call) instead of per-pixel hit-testing (O(w×h))
  • Gradient fills — fill_gradient_v and clear_gradient for vertical color transitions
  • Anti-aliased text — draw_char_scaled uses bilinear interpolation between source pixels for smooth scaled glyphs
  • Circle fill — integer edge-finding slice fill avoids per-pixel sqrt
  • Alpha blending — full RGBA blend compositing pipeline
  • Vector path icons — SVG-style compact binary path definitions (MoveTo/LineTo) with anti-aliased polygon fill

Implementation

ZirvTK is written in Rust and compiled with #![no_std] for freestanding MOSIX environments. It uses a custom arena allocator (16 MiB pool) when running outside a kernel allocator. The library communicates with the display through the ZirvFlux platform abstraction, which translates draw commands into buffer writes and presentation requests via the DisplayJet kernel driver.

The C FFI layer (c_api.rs + include/zirvtk.h) allows C compositors like ZirvUI to call into the Rust desktop compositor via ztk_desktop_run() and access raw framebuffer drawing functions (ztk_fb_*), vector path icon rendering (ztk_draw_icon_path), and font rendering.

Key design decisions:

  • Desktop renders every frame unconditionally (no dirty-rect tracking yet)
  • Event routing: taskbar click handled first; if handled, launcher toggled but not given the same MouseUp event (prevents immediate self-close)
  • Clock uses real RTC via getdatetime syscall, polled every 10 frames
  • msleep(16) removed from render loop — FPS is CPU-limited for maximum smoothness
  • VBE page flipping preferred over software double-buffer for zero-tearing display

Build

# Standalone (with ZirvFlux dependency)
ZIRVFLUX_DIR=../zirvflux cargo build --release --no-default-features --features alloc

# As submodule in Zirvium
cd /path/to/zirvium/zirvtk
ZIRVFLUX_DIR=../zirvflux cargo build --release --no-default-features --features alloc

Produces libzirvtk.a and libzirvtk.rlib.

Dependencies

  • zirvflux — Display framework
  • libm — Math library (sqrt, sin, cos for effects and rendering)
