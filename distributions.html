What is a MOSIX Distribution?

Just as Linux distributions (Debian, Arch, Fedora) all share the Linux kernel but differ in package management, init systems, and defaults, a MOSIX distribution is any operating system that implements the MOSIX standard. The standard defines:

  • The filesystem hierarchy (/bin, /lib, /user, /boot, /config, /zirv, /mounts, /tmp)
  • The /zirv device namespace (unified device tree replacing /dev, /sys, /proc, /run)
  • The syscall ABI (core Linux-compatible set + MOSIX extensions, x86-64 SYSCALL instruction)
  • The MAEM security model (optional, for in-memory encryption)

Zirvium is the reference distribution — analogous to how the Linux kernel is the reference for Linux distributions. Anyone can create a new MOSIX distribution by implementing the standard.

Approach A: Use Zirvium Directly

The simplest approach. Clone the Zirvium kernel and its submodules, build the ISO, and you have a fully functional MOSIX OS:

git clone https://github.com/gauthamnair2005/zirvium.git
cd zirvium
git submodule update --init --recursive
make run

This gives you: the Zirvium kernel, zirvlibc, zirvinit (PID 1), zirvshell (19 commands), and 17 embedded utilities. Everything boots from a single GRUB2 ISO.

Approach B: Fork Zirvium

Fork the repository and customise:

  • Kernel: Add new drivers, syscalls, scheduler, or architecture support
  • Userspace: Replace zirvinit, zirvshell, or zirvutils with your own implementations
  • Drivers: Port Linux drivers using the linux_compat.h API bridge
  • Branding: Change boot banners, shell prompts, distribution name

As long as you maintain the MOSIX ABI, your userspace programs remain compatible with other MOSIX distributions.

Approach C: Build From Scratch

Implement the MOSIX standard in your own kernel. You need:

1. Syscall ABI

Implement the MOSIX syscalls at the assigned numbers using the x86-64 SYSCALL/SYSRETQ mechanism. The core set covers file I/O, memory management, process control, time, and system power. See the MOSIX standard for the full table.

2. Filesystem Hierarchy

Create an in-memory or disk-backed filesystem with the standard MOSIX directories: /bin, /lib, /user, /boot, /config, /zirv (with sata, pata, nvme, usb, net, input, display, tty, audio subdirectories), /mounts, /tmp.

3. Console Device

At minimum, implement /zirv/tty/virtual0 as a read/write console device that accepts keyboard input and writes to a display (VGA text mode, serial, or framebuffer).

4. ELF64 Loader

Implement a static ELF64 binary loader that maps PT_LOAD segments, zero-fills BSS, and jumps to e_entry. Binaries are compiled with -static -no-pie -z max-page-size=0x1000.

5. C Library

Use zirvlibc as your userspace library, or implement the syscall wrappers yourself. The libc ABI is simple: each function maps to a _syscallN inline assembly wrapper.
