Boot Sequence

  1. GRUB2 loads the kernel ELF via Multiboot2 protocol and jumps to the 32-bit entry point.
  2. arch/x64/boot.asm: 32-bit stub checks for CPUID and long mode support, builds identity-mapped page tables (4 GiB via 2 MiB huge pages), creates a higher-half kernel map at 0xFFFFFFFF80000000, loads a 64-bit GDT, far-jumps into long mode, and calls kernel_main.
  3. kernel/main.c: Initialises serial, GDT, IDT, PIC IRQs, parses the Multiboot2 memory map, initialises the PMM and VMM, initialises the VGA text console, initialises the VFS tree, process table, embedded binary table, syscall entry, PCI bus, dynamic drivers, and PS/2 keyboard. Finally creates PID 1 and enters userspace.

GDT and Segment Layout

File: arch/x64/gdt.c, arch/x64/gdt.h

The GDT defines 6 entries for x86-64 long mode (segmentation is largely disabled but required for privilege-level transitions):

IndexSegmentDPLPurpose
0Null—Required null descriptor
1Kernel code0CS for ring-0 execution (L-bit set, 64-bit)
2Kernel data0DS/SS for ring-0 (writable)
3User code3CS for ring-3 execution (64-bit)
4User data3DS/SS for ring-3 (writable)
5TSS0Task State Segment (RSP0 on interrupt)

The TSS is set with a 16 KiB IST stack and is updated per-process: TSS.RSP0 is set to the process's kernel stack top before entering user mode, so that interrupts from ring 3 switch to the correct kernel stack.

Memory Management

Physical Memory Manager

The PMM uses a bitmap allocator (kernel/mm/pmm.c). One bit per 4 KiB page frame. Bit = 1 means used, bit = 0 means free. The bitmap is statically allocated in BSS (supports up to 1 TiB physical memory). The Multiboot2 memory map is parsed during boot to discover usable RAM regions; all other regions (firmware reserved, ACPI, MMIO) are marked unavailable.

API: pmm_alloc_page, pmm_free_page, pmm_alloc_pages, pmm_free_pages.

Virtual Memory Manager

The VMM (kernel/mm/vmm.c) manages x86-64 4-level paging (PML4 → PDP → PD → PT).

Memory layout:

0x0000000000000000 - 0x00007FFFFFFFFFFF   User space (per-process)
0xFFFF800000000000                        PHYS_MAP_BASE (direct physical map)
0xFFFFFFFF80000000                        KERNEL_VIRT_BASE (higher-half kernel)

During vmm_init: the first 4 GiB is identity-mapped (for early boot), the full physical memory is mapped at PHYS_MAP_BASE, and the kernel image is mapped at KERNEL_VIRT_BASE. Per-process address spaces clone the upper half (kernel) entries from the kernel PML4 and zero out the lower half.

Kernel Heap

A simple bump allocator over a 4 MiB static arena with a minimal free-list (kmalloc, kfree, kzalloc).

Process Management

Defined in kernel/proc/process.h and kernel/proc/process.c.

Process descriptor (process_t)

  • PID, state (UNUSED / RUNNING / BLOCKED / ZOMBIE)
  • Per-process address space (address_space_t *as)
  • User RIP/RSP, kernel stack top (used by TSS for ring-→ring 0 switches)
  • Heap state: brk, mmap_cursor
  • Open file descriptor table (64 entries, supports VFS nodes and pipe endpoints)
  • Parent/child/sibling pointers for process tree tracking
  • Current working directory (cwd[256])

User virtual memory layout per process

0x0000000000001000                     user code / data (loaded by ELF loader)
0x0000100000000000                     heap base (PROC_HEAP_START)
0x0000200000000000                     anonymous mmap region start
0x0000700000000000                     user stack top (grows downward, 64 KiB)

Process creation: proc_create allocates the descriptor, creates a fresh address space, pre-maps 16 user stack pages, links into the process list, and sets default CWD to /.

User mode entry: proc_enter_usermode switches to the per-process kernel stack, switches address space via CR3, and constructs an IRETQ frame to jump to ring 3.

Entry via SYSCALL/SYSRETQ instruction (arch/x64/syscall_entry.asm). The handler switches to a per-CPU kernel stack, saves callee-saved registers, reshuffles arguments (R10 → RCX), and dispatches to syscall_dispatch.

Inter-Process Communication

Ring-buffer pipes (kernel/ipc/pipe.c):

  • pipe_create allocates a 4 KiB circular buffer and read/write endpoints
  • pipe_read blocks until data is available (spin-loop, no scheduler yet)
  • pipe_write writes into the buffer, returns bytes written
  • pipe_destroy frees the buffer and marks endpoints closed
  • Pipe endpoints can be attached to process file descriptor tables

Virtual Filesystem

The MOSIX VFS (fs/vfs.c) builds an in-memory directory tree with the following standard paths:

/             root
/bin          system binaries (init, shell)
/lib          system libraries
/user         user home area
/boot         boot configuration
/config       system configuration
/zirv         device namespace
  /sata       SATA devices
  /pata       PATA devices
  /nvme       NVMe devices
  /usb        USB storage
  /net        network interfaces
  /input      input devices
  /display    display devices
  /tty        terminal devices
    /virtual0 console device (keyboard + serial input, VGA+serial+fb output)
  /audio      audio devices
/mounts       mount points
/tmp          temporary files

The console device at /zirv/tty/virtual0 provides read/write operations that aggregate input from both the PS/2 keyboard and serial port, and output simultaneously to VGA text mode, pixel framebuffer, and serial UART.

Interrupts and IRQs

  • 8259A PIC initialisation, IRQs 0–15 mapped to IDT vectors 32–47
  • request_irq / free_irq / irq_dispatch / irq_eoi / irq_mask / irq_unmask
  • Supports shared IRQs and edge triggering
  • 256 ISR stubs generated in arch/x64/isr_stubs.asm

Drivers

PCI

Full PCI bus enumeration (drivers/pci/pci.c) with configuration-space access, BAR reading, and driver-vendor matching.

Storage

  • SATA/ATA PIO (drivers/zirv/sata.c): Full ATA PIO driver with IDENTIFY, sector read/write (LBA28), device type detection
  • NVMe (drivers/zirv/nvme.c): Polling-mode NVMe PCIe SSD driver
  • USB storage (drivers/zirv/usb_storage.c): USB mass storage stub

Input

  • PS/2: i8042 controller init, keyboard (with ASCII translation), Synaptics touchpad

Display

  • VGA text mode (drivers/vga/vga.c): 80x25 text console at 0xB8000
  • Framebuffer console (drivers/vga/fb_console.c): Pixel framebuffer text renderer
  • Bochs VGA, VMware SVGA, Intel i915 graphics drivers
  • DisplayJet (drivers/zirv/displayjet/): MAEM-encrypted display driver with surface management, ChaCha20 per-surface encryption, and DMA fencing

Networking

  • Intel e1000, VirtIO net, Realtek RTL8139

Other

  • Serial: 16550 UART on COM1 at 115200 baud
  • HDA Audio: High-Definition Audio controller
  • TPM 2.0: Trusted Platform Module
  • Realtek Bluetooth
  • WiFi: Realtek RTL8723DE

Dynamic Driver Framework

Drivers register via driver_register with a vendor/device ID table. driver_probe_all iterates PCI devices and matches against registered drivers, calling each driver's init function on match. Each device gets a /zirv namespace entry via zirv_register_device.

ELF Binary Loader

Static ELF64 loader (kernel/loader/elf.c) that:

  • Validates ELF header (magic, 64-bit, little-endian, version)
  • Iterates PT_LOAD program headers
  • Allocates physical pages and maps them into the process address space at the virtual addresses specified in the ELF
  • Zero-fills the BSS segment
  • Sets the process entry point from the ELF header's e_entry

Init and shell binaries are embedded into the kernel via NASM incbin (kernel/loader/init_bin.asm). The embedded_init function records their addresses, and embedded_find looks up by path (/bin/init, /bin/shell).
